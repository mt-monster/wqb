### 11.1 为什么必须分开评两件事

base 与池增益是**两条正交的账**，且方向常常相反：

|---|---|---|---|
| PC | **越低越好**（<0.30 进 553） | 越低越好 | 同向 ✅ |
| self | 无要求 | **越低越好** | — |
| S / F | **越高越好**（≥5 双5 门槛） | 越高越好（边际 Sharpe） | 同向 ✅ |
| 组件数 | 少（压 prod） | 多（分散） | ⚠️ 冲突 |
| 塔倍率 | 高倍率类 | 不影响 | — |

⇒ 实质冲突只有一处：**组件数**（§`super_alpha_params.md`：组件数↑ ⇒ self↓ 但 prod↑）。其余同向。

### 11.4 池增益层：可算，但幅度极小

池指标取自 `get_leaderboard()`：`superAlphaSubmissionsCount` / `superAlphaMeanProdCorrelation` / `superAlphaMeanSelfCorrelation`（2026-11-22：**58 / 0.6301 / 0.5976**）。

**正增益定义（三项同时成立）**：

1. `PC_new < 0.6301` —— 拉低池 PC 均值
2. `self_new < 0.5976` —— 拉低池 self 均值
3. `mutual_new < 0.70` —— 不与池内任一 SA 孪生（≥0.70 硬拦）

**幅度**：`Δmean = (x − mean) / (n + 1)`

| 场景 | Δmean_PC |
|---|---|
| x = 0（理论极限） | **−0.0107** |
| x = 0.30（553 上限） | −0.0056 |
| x = 0.63（= 池均值） | 0 |

⇒ **单颗对池均值的拉动 ≤ 0.011，统计上不可检测**。所以「池增益」只能是**方向性记录**，不能宣称「交了之后池子变好」。

**真正会改变池结构的**只有两件事：
- 累积多颗 PC<0.30 的 SA（把 58 颗均值的左尾做厚）
- 不再往均值以上加件（停止稀释）

### 11.5 反向成本（2026-11-22 实测更正：**按 PC 分层**，不是一律计负）

`prod_correlation` 的定义是 **取 max**：`prod(new) = max(corr(new, 池内每一颗))`。
⇒ 加入新成员对后续候选的 prod **只会「不降、可能升」**（数学单调性），**是否真抬取决于新成员与后续候选的相关**。

**分层结论：**

| SA 类型 | 与 RA 的相关 | 对后续 RA 的 prod | 真实成本 |
|---|---|---|---|
| **低 PC 的 SA**（如 `A1xmpg9R` PC .5178） | **仅 .067–.283**（与 KOR 全部组件实测） | **≈ 0**（远低于 KOR 组件自身 0.5–0.69 的 prod 水位） | 只占坑位 |
| **高 PC 的 SA**（与 RA 同骨架） | 高 | 明显抬升 | 污染 RA |

**`A1xmpg9R` 的 0.5178 最近邻是另一颗 SA `KPg60XNp`，不是任何 RA 组件** ⇒ 它是「干净的后来者」。

**⇒ 判定时按 PC 分层：PC<.55 的 SA 不计「污染 RA」负项；真正的成本是 ① 占 SUPER 配额 ② 锁住同族 SA（新 KOR SA 需同时避 `KPg60XNp` 与它）③ base 增量 $0–0.5/日且不可分辨。**
（历史警示仍有效：提交**同骨架**变体后 self 飙 0.99 全族死、PC 窜到 0.9+ ——但那是同骨架情形，不是低 PC 新件。）

### 11.6 判定顺序与退出码

```
1 REDLINE       prod ≥ .70 ｜ mutual ≥ .70 ｜ checks FAIL        → exit 3 硬拦
2 UNDETERMINED   prod/self/mutual 任一缺失                       → exit 4 阻塞
3 BELOW_TIER    S<5 或 F<5（档位不到双5）                        → exit 1 待裁定
4 GO            档位≥双5 ∧ PC↓ ∧ self↓ ∧ 乘数≥4                 → exit 0
5 HOLD          档位达标但池改善只满足一项，或乘数<4              → exit 1 待裁定
```

**注意**：`mult < 4` 判 HOLD 用的是本账户口径——无主题（theme=1.0）+ 单类塔（1.1）时 `mult = 1.1×1.85 = 2.04`，这类件在 §9.3 里从未产生过可测 base。

### 11.7 与 VF 闸的关系

**VF 闸（铁律 14）对 SA 没有对象**：`value_factor_trendScore` 只统计 REGULAR，SA 不进 N/A/P ⇒ 相似度分项 0 贡献。

⇒ SA 走本闸（base + 池），RA 走 VF 闸（相似度 + 拖累条件），**两闸不重叠、不可互相替代**。

## 12 ★ 官方收入公式与论坛 VF 实证（2026-11-23 取证，SA 收益最大化的底层框架）

> 来源：India/Kenya 2022 Base Fee 官方存档文档（scribd）+ 三篇顾问中文论坛一手实证。
> 本节**不改任何档位/金额锚点**（前文 §9.3 本账户实证仍是权威），只纠正「优化方向」的优先级。

### 12.1 官方 Base Fee 公式（六维 Quality Factor）

```
AggregateFactor = f(QualityFactorScaled + QuantityFactorScaled, SelfGrowthFactor, ValueFactor)
Daily Base      = f(AggregateFactor)      # 连续非递减
Daily Limit     = 前 4 个 RA + 前 1 个 SA  # 超额白交
```

**Quality Factor 是六维（此前记五维是漏了 MTheme，2026-11-23 纠正）**：

| 维度 | 官方定义 | 本账户可控性 |
|---|---|---|
| MCorrelation | 与 WQ 池相关性越低越高 | ✅ 主战场（PC） |
| MRegion | 欠探索区加权越高 | ⚠ 账户区池选择，非单颗 SA 可调 |
| MUniverse | 票池越大越高 | ⚠ 同上（TOP600 vs TOP3000） |
| MFitness | fitness=f(turnover, sharpe, returns) | ✅ |
| MDelay | delay 价值，公司定 | ❌ 固定 delay 1 |
| **MTheme** | **主题激励，公司公布** | ⚠ theme 命中是六维之一，不只是外部乘数 |

**SelfGrowthFactor** = `f(CurrentQuantity, CurrentQuality, PastQuantity, PastQuality)` —— **相对自己历史的进步**。
⇒ 断更、质量环比倒退会直接掉 base；连续稳定提交本身有收益。
**ValueFactor 三要素** = ①单件表现 ②近期提交多样性 ③**相对自己过去 + 他人提交的独特性**。

### 12.2 论坛实证（VF 是唯一强相关，非线性台阶）

| VF | 日均 base | 出处要点 |
|---|---|---|
| 0.5（初始） | $1.2–6 | 约 3 个月首次更新，初始值固定 0.5 |
| **0.97** | ~$35 | 「主要靠 SA 赚」，SA 只要 fit>5、prod<0.7 就稳定 |
| 0.99 | $60–80，偶破$100 | **仅比 0.97 高 .02，收入近翻倍＝非线性台阶** |
| 1.00 | $104.91（单日） | 上限 |

三条决定性原话级结论：
1. **VF 由过去 3 个月提交综合质量评定**，各地区组合对 VF **等权**，没交过的区不计入统计
   ⇒ 一个个区深耕、别铺太散（这正是 §「USA+EUR 集中⇒VF 暴跌」的机制解释）。
2. **提交看边际不看绝对**：fit 1.03/self .1 提升地区组合 ＞ fit 1.98/self .68 降低地区组合
   ⇒ `performance_comparison` 应前置为排序首要判据（已在 `13_submit_preflight_order.md` Stage5 + `sa_submit_gate.py` 落地）。
3. **SA/RA 分工**：SA 不点塔、不进 S_P，只刷 base；每天 1 颗足够（Daily Limit=1）。
   VF 的建设靠 RA 的数量×质量×地区均衡 ⇒ **养 VF 靠 RA，收割 VF 靠 SA**。
