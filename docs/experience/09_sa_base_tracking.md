# 09 · SA 提交 × Base 增长追踪方案

> 建立日期：2026-11-20 ｜ 台账目录：`tracking/SA_BASE/`
> 目的：把「每天交了什么 SA」与「base 每天到账多少」做成一条可回归、可证伪的时间序列，用来判定 base 增长到底由什么驱动。
> 本方案只记录与评估，**不赋予任何提交权限**（`ALLOW_ALPHA_SUBMIT=False` 不变）。

---

## 1 为什么现在需要它：一个月的数据已经把问题问清楚了

把 `get_daily_and_quarterly_payment` 的 102 条到账记录按 `月 base = 有付天数 × 有付日均` 拆开：

| 月份 | 自然天 | 有付天 | 覆盖率 | 合计 | **有付日均** |
|---|---|---|---|---|---|
| 2026-08 | 31 | 23 | 74.2% | $36.80 | **$1.600** |
| 2026-09 | 30 | 22 | 73.3% | $38.04 | **$1.729** |
| 2026-10 | 31 | 28 | 90.3% | $47.28 | **$1.689** |
| 2026-11（1–18） | 18 | 18 | **100%** | $29.61 | **$1.645** |

精确分解 `Δ = Δn·p_prev + n_curr·Δp`：

| 区间 | 来自天数 Δn·p | 来自日均 n·Δp | 合计 |
|---|---|---|---|
| 08 → 09 | −1 天 ⇒ **−$1.60** | +$2.84 | **+$1.24** |
| 09 → 10 | +6 天 ⇒ **+$10.37** | −$1.13 | **+$9.24** |

**两条结论，都是硬的：**

1. **10 月那 +$9.24 里，112% 来自「有付天数 +6」，日均反而微降。**
2. **有付日均连续 4 个月在 $1.60–1.73 横盘，相关系数对时间 ≈ 0，没有趋势。**

⇒ 到目前为止，base 增长**全部**来自「把空转日填满」，而不是「把每格填厚」。而覆盖率在 11 月已经打到 **100%**——这条腿**已经用尽**。

## 2 覆盖率见顶之后，只剩一个变量

```
月 base = 自然天数 × 覆盖率 × 有付日均
           └── 固定 ──┘  └ 100% 已到顶 ┘  └ 唯一还能动的 ┘
```

而日均按官方口径是四个乘子：

```
有付日均 = 基准额 × f(VF) × (1 + Osmosis_Rank) × 主题乘数 × (SA/RA 组合的结构项)
```

当前读数（2026-11-20）：

| 乘子 | 当前值 | 理论区间 | 若拉满的倍数 |
|---|---|---|---|
| Value Factor | **0.73**（今日由 0.43 上调） | 0–1+ | 未知，且非线性的可能很大 |
| Osmosis Rank | **0.53** ⇒ 乘数 **1.53**（11-20 实测；午间 0.27 为旧值） | 0–1 ⇒ 1–2 | **×1.18**（到 0.80） |
| 主题乘数 | **未吃到**（base 曲线从无尖峰） | 1–3 | **×3** |
| SA/RA 结构项 | 未知 | — | 未知 |

**⇒ 三个乘子里，量级最大的是 Osmosis Rank（×1.42，确定性最高）和主题（×3，门槛最高）。VF 是慢变量且今日已跳一档，正好构成一个自然实验。**

## 3 台账设计（三张表，职责分离）

目录 `tracking/SA_BASE/`：

### 3.1 `sa_daily.jsonl` —— 提交面（append-only）

一天一行，记录当日提交的 SA：

| 字段 | 含义 |
|---|---|
| `date_et` | **ET 交易日**（= 配额日，GMT+8 次日 13:00 前算同一日） |
| `n` / `ids[]` | 当日提交颗数与 id |
| `region` / `universe` | 主件所在区 |
| `S` / `F` / `prod` / `self` / `TO` | **当日最好一颗**（按 F 取）的六项指标 |
| `axes`（后续新增） | 配方五轴：`sel_key` / `to_cap` / `limit` / `combo` / `neut` |

### 3.2 `base_daily.jsonl` —— 收益面（**按日 upsert，可回补**）

| 字段 | 含义 |
|---|---|
| `date_et` / `base_usd` | ET 日与当日 base |
| `rev` | 首次写入时的时间戳（区分「原始值」与「回补值」） |

> ⚠ **base 会延迟到账**：11-19 已提 REGULAR 但当日 base 仍为 0。故每日任务必须**回读最近 14 天并覆盖写入**，不能只 append。

### 3.3 `account_daily.jsonl` —— 账户面协变量（append-only）

| 字段 | 来源 | 为什么要它 |
|---|---|---|
| `vf` / `os_rank` / `multiplier` | `get_leaderboard` | 两个乘子，直接进模型 |
| `diversity_score` / `S_A` / `S_P` / `S_H` | `value_factor_trendScore` | 拆 VF 的多样性成分 |
| `N_regular_window` / `P_pyramid` / `P_max` | 同上 + 平台 216 | S_P 的分子分母 |
| **`os_active_total` / `os_active_super` / `os_active_regular`** | `get_user_alphas(status=ACTIVE, limit=1)` 读 `server_count` | **上一轮回归漏掉的关键协变量**：base 很可能 ∝ 在册 alpha 数，而不是 SA 质量 |
| `meanProdCorrelation` / `sa_meanProdCorrelation` / `sa_meanSelfCorrelation` | `get_leaderboard` | 结构面，用于排除「交了但池子变差」 |
| `dataFieldsUsed` | 同上 | T4 铺开度的代理 |

> **上一轮 41 天回归只放了 SA 的 S/F，没放 `os_active_*`，这是遗漏变量。** 覆盖率从 74%→100% 与在册 alpha 数同步上涨，很可能同源。本台账的首要任务就是把这两个变量拆开。

## 5 评估模型（三层，逐层收紧）

### L1 描述层 —— 每月一次
就是 §1 那张表。**唯一 KPI 是两个**：`覆盖率` 与 `有付日均`。任何 base 变化先问「是哪一项动了」。

### L2 归因层 —— 每周一次
用 `Δ = Δn·p_prev + n_curr·Δp` 做加减法分解，再对日均做二阶归因：

```
有付日均 = α + β₁·VF + β₂·OS_rank + β₃·ln(os_active_total) + β₄·SA_F + ε
```

样本量约束（实测 `sd(日均) = 0.180`）：

| 想检出的位移 | 每组所需天数（power 80%, α=.05） |
|---|---|
| +$0.30/天 | **3 天** |
| +$0.20/天 | **6 天** |
| +$0.10/天 | **25 天** |
| +$0.05/天 | **102 天** |

⇒ **能测到 +$0.2，测不到 +$0.05。** 任何小于 $0.1 的结论一律写「不可分辨」，不许当结论。

### L3 因果层 —— 只在有自然实验时做
不做随机化，只等平台自己给出断层（见 §6）。

## 6 三个待验假设 + 一个正在进行的自然实验

### E1（**已开始，2026-11-20**）VF 0.43 → 0.73
- 处理组：11-21 起的有付日均
- 对照组：11-01~11-18 的 $1.645（n=18）
- 判定：**若日均 ≥ $1.85（+$0.20）且持续 ≥6 天 ⇒ VF 有杠杆**；若仍在 $1.55–1.75 ⇒ **VF 在 0.4–0.7 区间对日均无杠杆**，base 增长只能靠 OS/主题。
- 这是本方案第一个、也是最便宜的实验，代价为零（本来每天都到账）。

### H1 有付日 ⟺ 当日有提交
- 证据：11 月 18/18 全有付，且 18 天每天都有 RA 或 SA 提交；10 月 28/31，3 个空转日（10-11、10-16、10-23）里有 2 天完全没提交。
- 反例：10-23 交了 SA `kqJOQgnk` 但无到账。
- 判定：累积 ≥20 个「有提交但 0 到账」样本 ⇒ 假设推翻；≥30 个「无提交但到账」⇒ 推翻。**当前覆盖率 100%，短期内无法再检验，只能当守门规则。**

### H2 SA 质量（S/F）→ 日均
- 已测：41 天 corr(base, SA_F) = **−0.115**，F≥5 的 8 天均值 $1.607 vs F<5 的 33 天 $1.714。
- 判定：**若累计 n≥60 天仍 |corr| < 0.2 ⇒ 关闭该假设**，不再为 base 而挑 SA。

### H3 SA 质量 → Osmosis 入选 → OS Rank → 乘数
- 机制依据：官方 `Osmosis Allocation Guide` 明写可分配点数含 SuperAlphas，且 Daily Osmosis Rank 是 **1–2 的乘数**。
- 这是**唯一一条量级够大的 SA→base 通道**（×1.42 到 ×2，远大于任何 SA 直接贡献）。
- 判定：每周记录 `os_rank`，与 SA 池均值 S/F 做滞后相关；若 `os_rank` 随 SA 质量上行 ⇒ 这才是 SA 的正确用法。

## 7 决策触发线

| 条件 | 动作 |
|---|---|
| E1 显示日均 ≥ $1.85 持续 6 天 | VF 进模型；把「抬 VF」列为第一优先级（扩 pyramid，靠 REGULAR） |
| E1 显示日均不变 | **VF 不是日均的乘子**，停止为 VF 交 SA；转攻 OS Rank |
| 覆盖率 < 100% 且日均横盘 | 优先「填满空转日」（交任意合规件），这是历史上唯一验证有效的手段 |
| H2 累计 n≥60 且 \|corr\|<0.2 | 关闭「SA 质量→base」，SA 只按 RA 闸与塔判定交 |
| **`os_rank ≥ 0.50`** | **乘数 ≥ 1.50 ⇒ 全账户 base ×1.18**；若同时 `os_rank` 与 SA 池质量相关 ⇒ 重新定义 SA 的选件标准 |
| 某月日均环比 ≥ +10% 且覆盖 100% | 记录该月的乘子组合作为模板，后续复制 |

## 8 已知局限（写在这里防止过度解读）

1. **`get_daily_and_quarterly_payment` 只给到账值，不给公式。** 所有 β 都是观测相关，不是因果系数。
2. **历史 `os_active_*` 不可回溯**（平台无历史快照），L2 回归只能从 2026-11-20 起累积，前 3 个月无法补协变量。
3. **base 有到账延迟**，最后 1–2 天必须视为「未定」，不得进均值。
4. **11 月只统计到 11-18**，是残缺月，不能与整月环比。
5. **主题乘数无法观测**（平台不公布是否触发），只能通过 base 突增 + 检查 `MATCHES_THEMES` 反推。
6. 本台账**不产生提交动作**。任何 SA 是否提交仍由用户单独决定。
