## 1 核心公式（论坛实测反推，非官方）

```
最终乘数 = (Theme + Pyramid − 1) × (1 + Osmosis Rank)
日 Base  = Base基准 × VF × 最终乘数 × (PC 台阶因子) × Fitness 因子 × Quantity
```

**Base 由 4 个因子组成**（BRAIN Tips 003）：Quality × Quantity × SelfGrowth × ValueFactor。
**Theme 只放大 Quality Factor，不影响季度奖金**；且质量/数量因子是**相对其他顾问缩放**的，**3X ≠ 收入直接 ×3**。

**三条决定性结论：**

1. **高乘数是必要前提**：A（3.49）vs B–I（≥5.2）——没有放大器，VF 再高也冲不上。
2. **PC < 0.3 是台阶式放大器**：H/I 的 Sharpe（2.34/2.00）、Fitness（2.25/2.20）都远低于 C/D，
   但 PC 压进 0.25 以下，Base 从 $6–8 跳到 **$36–39**（**×4~5**）。同乘数下 PC 0.68 与 PC 0.21 的差距是量级的。
3. **Fitness > 2.0 是门槛**：B/C/D 同为高乘数、PC 都在 0.6–0.7，**Fitness 越高收益越高，但 PC 不降就难破 $8**。

## 3 Theme 机制（BRAIN Tips 003，2026-11-17）

### 3.1 三种 Theme

| 类型 | 是什么 | 对收入的影响 |
|---|---|---|
| **日常 Alpha Theme** | 全平台 Theme / **个人 Theme**（分配给你的，别人的不一定适用） | 命中 ⇒ Theme Multiplier，放大质量因子 |
| **Power Pool Theme** | 规定 Power Pool Alpha 的区域/Delay/数据类别 | 决定能否提交 + 参与竞赛排名；**Multiplier = 1X**（无加成） |
| **Pyramid Theme** | 按「区域 × Delay × 数据集类别」划分，**使用率越低的组合倍数越高**，可能每天变化、不另行通知 | Pyramid Multiplier，放大质量因子 |

### 3.2 怎么查 Theme
1. **看 Announcement**（每次 Theme 更新平台都会发公告）
2. **看 Alpha 回测结果的 `IS Testing Status`** —— 任意一条完整回测（full simulation）的 Alpha，打开后**会写明它命中了哪些 Theme、没有命中哪些**

### 3.3 Theme 倍率排序（10-23 帖 + 10-22 帖实测）

```
GLB ARC THEME  >  3X THEME  >  2.5X THEME  >  2X THEME
```

- 常见档位：**普通 2X（但 python 3X）**｜**直接 3X（如 ASI）**｜**GLB 普遍 2.5X，没有 python**
- **GLB theme 比其他 region 的乘数高 0.5**
- **ARC 加成：区越多加成越多**；ARC 规则「多一区加一分，Sharpe>2 额外加 1 分」
  ⇒ 实测 **VF 0.61 + OS 0.94 + 4 区 ARC + theme → $60**；3 区只有 $14
- ⚠ 「明面倍率不准确」：作者 4+ 倍也能吃满，7 倍也会只吃一点

### 3.4 GLB 推荐数据集（GLB/D1 Power Pool Nov'26 公告，**2026-11-22 截止**）

`pv1`、`model110/77/26/109/38/50/264/138/30`、`risk70/68/60`、`analyst69/15/14/11/10`、
`other460/455/432/496/553`、`fundamental23/17/28/6/72/44`、`pv37/53/96`

> ⚠ 该主题是 **Power Pool Theme（1X）+ 竞赛奖金池 $15,000**，**不是 3X 的 Alpha Theme**。别把它当乘数来源。

## 4 PC（Prod Correlation）的三个档位

| PC 区间 | 收益表现 | 备注 |
|---|---|---|
| **< 0.25** | **台阶式放大（×4~5）**，单日 $30–40 的起点 | 拉开量级的关键，权重**超过** Sharpe/Fitness |
| **0.3 – 0.6** | 中等，$4–9 | — |
| **0.6 – 0.7** | 低档，$1.5–2.5（不做主题时） | 用户当前所在区间 |
| **> 0.7** | **收益缩水约 40%，且影响 VF/WF 增长** | **红线，必须避开** |

**Fitness 的隐藏加成甚至超越 PC**：fit2 的 RA 哪怕 PC 超 0.7，收益都能跟 PC<0.3 的 fit1 持平。
档位：**fit5 > fit2 > fit1**。

### 降 PC 的手法

**RA 侧**：
- **捡漏 `alpha_count = 0` 的新数据集字段**（被挖掘程度最低，捡漏空间最大）
- 拥挤度速查 `datasets.alpha_count`，选冷门子集
- 终极解 = 换数据集 / 换信息机制

**SA 侧**（JPN 帖，PC 由**底层成分池**决定，不是 combo）：

| 梯队 | 手法 | 实测效果 |
|---|---|---|
| ⭐⭐⭐ 一 | **换池 / 错开 band** | 找 PC 谷，可低 0.2–0.3；**每次重建第一步就是错开最近被提交 SA 所在 band（上下相邻 1–2 档）** |
| ⭐⭐⭐ 二 | **self_correlation 收紧到 0.20** | 同 band 下 PC 0.400 → 0.311；**0.20 是甜点**（0.18 起 Fitness 跌破 5，0.15/0.12 全崩） |
| ⭐⭐⭐ 三 | **combo nlength = 126 / 140** | 短窗通常更降 PC |
| ⭐⭐ 四 | operator_count 收紧 <7→<6 | 再降 ~0.02，但每档压 Sharpe，<5 崩 |
| ⭐⭐ 五 | 排除拥挤数据类别（`not(in(datacategories,"analyst"))` 等） | 某些池是最大单杠杆（−0.058），代价 Fitness ≈ −0.9，**不可贪心** |

**⚠ 核心机制：提交 = 污染**。一条 SA 提交后成为自有 alpha，**同 band 同结构的下一条 PC 直接飙到 0.9+**（实测 0.29 → 0.97）；
**整个谷每提交一条整体上移 ~0.06**。⇒ **"挖 553"是持续重建，不是一劳永逸；同一批候选同池同构，交其一必废其余。**

**SA 可复现配方（JPN 553 模板）：**
```
region/universe : JPN / TOP1600      delay : 1
neutralization  : STATISTICAL        truncation : 0.08
selectionLimit  : 300    nanHandling : ON    maxTrade : ON    decay : 6~8
selection:
  not(own)
  && (prod_correlation<0.50 && prod_correlation>0.44)      # band：每天重扫
  && (operator_count<7 && operator_count>2)
  && (self_correlation<0.20 && self_correlation>0.05)
  && not(in(datacategories,"analyst")) && not(in(datacategories,"model"))
combo:  combo_a(normalize(alpha), nlength=126, mode='algo1')
```
**JPN/TOP1600 + delay=1 是社区唯一实证「能同时保双5 且 PC<0.3」的池**（IND/GBR/EUR/USA/CHN/ASI 实测均无解）。

**证伪清单**：换中性化（除 STATISTICAL）升 PC｜combo 换 algo2/3/4 升 PC｜多周期 mix 多数池升 PC｜
双 band OR 升 PC｜窄 band（±0.02）Fitness 崩｜universe=TOP1200 S/F 崩｜selection 加 `dataset_count>1` Sharpe 崩到 3.5｜收紧 prod_correlation 阈值双指标断崖。

## 5 Osmosis Rank（OS）怎么提

### 5.1 门槛（11-19 帖 + 11-02 帖）
```
OS > 0.5 → 考虑吃 BASE（RA 40+）
OS > 0.6 → RA 50+
OS 0.9+ → SA 双5 也能 50+
OS < 0.5 → 乖乖点塔
```
**没有 OS daily rank，收益缩水高达 80%。**

### 5.2 点数分配（11-02《个人 OS 分配经验总结》）
- **不要「全配」**：margin 刚过地板的 alpha，净因子 ≈ 0，**把有限分数分给了不产生净收益的 alpha**。
  作者一个 region 的达标池里**超过七成**挤在「地板往上不到 50%」区间。
- **硬过滤**：退市 / `COMPENSATED_ALPHA` WARNING / Fast D1 / 零仓位 / **margin < 本 region 地板**
- **二次过滤：margin ≥ 1.5 × 地板**
- **每个 scope 至少 12 条**（平台下限 10，留 2 条缓冲防退市）；不足时按 margin 降序补足，补进来的仍必须 ≥ 地板
- **权重**：70% 等权核心 + 30% 给打分 top-5 卫星，且**卫星两两 ρ ≤ 0.70**
  （稳健组和爆发组底层逻辑隐性关联是最隐蔽的坑）
- **换手 > 20% 尽量避免**（Osmosis 最终考虑成本）
- **读数噪声大**：规则是**周日锁定 → 两周后才用于计算**；**同一份配置一周内读数能差好几倍**，单日读数别当结论

### 5.3 研究小组门槛（11-06，可作为 OS 的参照线）
- 邀请条件：自然周内平均 **Osmosis Rank > 0.3**；平均 PC < 0.7；当周提交 > 5 个且含至少 1 个 GLB
- 成员保持：当周 PC < 0.7；**每周至少 1 个 GLB Alpha**；自然周平均 OS > 0.3

## 6 保 VF 的纪律（9-28 帖，VF 暴跌的反向教训）

1. **提交数量必须稳定**：窗口期内月度差异过大 ⇒ VF 震荡（作者 VF 一路跌到 0.45）
2. **质量优先，不要「绿了就提交」**：为点塔交质量一般的因子，会拖垮 VF
3. **地区要分散**：USA+EUR 过度集中 ⇒ 相关性持续走高 ⇒ VF 暴跌；**建议适度开小地区**
4. **坚持做 SA，无论 VF 高低**：窗口期内 PPA/RA 数量骤降时，靠持续的 SA（保持 553 或 35 标准）保住 VF 不至于坐牢

## 8 落地优先级（RA / SA 分列）

### RA（主战场，量级最大）
1. **【最高】把主力切到 GLB**，用 GLB 主题推荐数据集，目标命中 **3X / GLB theme**
2. **【最高】把 PC 从 0.57 压到 <0.3**：捡漏 `alpha_count=0` 新字段、选冷门数据集
3. **【高】Fitness 提到 >2.0**（门槛，fit5 > fit2 > fit1）
4. **【高】OS 从 0.53 推到 0.6+（0.8 更好）**：按 §5.2 重配 Osmosis（margin ≥1.5×地板、每 scope ≥12 条、卫星 ρ≤0.70、避开 TO>20%）。**0.53 只是刚过门槛，0.6 才是 40+ 的线**
5. **【高】保住 OS 不回落到 0.5 以下**——越过 0.4→0.7 区间存在远超线性的台阶（见 §7 对照），掉回去代价极大
5. **【中】保持每周 ≥1 个 GLB**（研究小组门槛 + GLB 乘数最高）
6. **【保 VF】提交节奏稳定、质量优先、地区分散**

### SA
1. **【最高】把 prod 闸从 ≤0.65 收紧到 <0.30**——否则在 OS<0.5 下永远拿不到 50+
2. **【最高】换池**：JPN/TOP1600 D1 是社区唯一实证可同时保双5 且 PC<0.3 的池（本账户从未试过 JPN）
3. **【高】错开 band + self_correlation<0.20 + combo nlength 126/140**
4. **【高】neutralization 只用 STATISTICAL**（换族升 PC，已证伪）
5. **【中】补 GLB SA**（GLB theme 乘数最高），但本账户 GLB SA 的 F 缺口是结构性问题，需重新评估「不达双5 但命中 GLB theme」是否仍有加成
6. **【不变】SA 的 S/F 对 base 无可测杠杆**（41 天回归 corr −0.115）；SA 的主攻方向是**降 PC**，不是提 S/F
