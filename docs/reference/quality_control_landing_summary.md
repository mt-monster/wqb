### 1.2 四层质量把控

| 层面 | 检查项 | 拦截标准 | 输出 |
|------|--------|----------|------|
| 模板质量层 | 经济学逻辑、字段匹配、构造链完整、机制覆盖、历史表现 | 无经济学含义 → 拦截 | 模板质量评分 + 改进建议 |
| 字段质量层 | 覆盖率、更新频率、数据类型、形状分布、竞争度、历史表现 | coverage < 0.6 → 拦截 | 字段质量评分 + 可用性标记 |
| 表达式质量层 | 语法正确、结构合理、多样性、配额合规、字段重复、机制匹配 | 语法错误 → 拦截 | 表达式质量评分 + 风险标记 |
| 回测质量分析层 | 达标率、信号苗头、CW 墙、PROD 相关性、机制表现、字段表现 | 达标率 < 10% → 告警 | 回测质量报告 + 信号苗头清单 + 失败原因诊断 |

## 二、质量评分体系

| 评分等级 | 分数范围 | 含义 | 动作 |
|----------|----------|------|------|
| A | 90-100 | 优秀 | 直接通过 |
| B | 80-89 | 良好 | 通过， minor 改进 |
| C | 70-79 | 合格 | 通过，需要改进 |
| D | 60-69 | 不合格 | 拦截， major 改进 |
| F | 0-59 | 失败 | 拦截，重新设计 |

---

## 三、质量改进控制流程

模板设计 → 模板质量检查 → 字段选择 → 字段质量检查 → 表达式生成 → 表达式质量检查 → 回测执行 → 回测质量分析 → 质量报告

---

## 四、使用方式

`python
from quality_control_engine import QualityControlEngine

# 创建引擎
engine = QualityControlEngine()

# 运行完整质量检查
report = engine.run_full_check(wave_data)

# 查看总体质量评分
print('模板质量：', report['summary']['template_score'])
print('字段质量：', report['summary']['field_score'])
print('表达式质量：', report['summary']['expression_score'])
print('回测达标率：', report['summary']['backtest_pass_rate'])

# 查看改进建议
for suggestion in report['overall_suggestions']:
    print('-', suggestion)
`

## 七、持续改进机制

### 7.1 质量数据收集

| 数据 | 收集方式 | 用途 |
|------|----------|------|
| 模板质量数据 | 每次模板质量检查 | 优化模板设计 |
| 字段质量数据 | 每次字段质量检查 | 优化字段选择 |

### 7.2 质量指标看板

| 指标 | 计算方式 | 目标 |
|------|----------|------|
| 模板质量平均分 | 所有模板质量评分平均 | >= 80 |
| 字段质量平均分 | 所有字段质量评分平均 | >= 75 |
| 表达式质量平均分 | 所有表达式质量评分平均 | >= 85 |
| 回测达标率 | 达标表达式数 / 总表达式数 | >= 15% |
| 信号苗头发现率 | 信号苗头数 / 总表达式数 | >= 20% |

## 八、总结

质量改进控制体系通过四层质量把控（模板/字段/表达式/回测）和持续改进机制，确保挖掘因子流程的质量和效率。

核心价值：
1. 预防为主：在模板设计、字段选择、表达式生成阶段前置拦截质量问题
2. 层层拦截：每个阶段都有质量检查，避免问题传递到下一阶段
3. 数据驱动：基于历史数据和回测结果生成改进建议
4. 持续改进：通过质量数据收集和指标看板，持续优化挖掘策略

预期效果：
- 模板质量提升 20%
- 字段质量提升 15%
- 表达式质量提升 25%
- 回测达标率提升 30%
- 信号苗头发现率提升 40%
