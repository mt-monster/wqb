# 机制 × 字段 搭配手册（DEU 战役实证版 · 2026-10-07）

> 来源：单会话 **≈375 次字段/机制测试**，覆盖 DEU 的 MODEL / ANALYST / FUNDAMENTAL / PV 四个 category。
> 本文回答三个问题：**有哪些机制？字段怎么分类？哪一类该怎么配？**
> 所有结论均带实测证据；**没测过的明确标注**。

---

## 一、机制总表（按"信号的时间结构"分类，这是最有解释力的分法）

| # | 机制 | 一句话 | 典型构造 | 本会话实测 |
|---|---|---|---|---|
| **M1** | **变化率水平** | 预期/指标"正在往哪个方向动" | `add(ts_mean(bf,w1), ts_mean(bf,w2))` | ✅ **唯一成功族** |
| **M2** | **修正广度** | 多少人在上调 vs 下调 | `subtract(rank(up), rank(down))` | ❌ 全灭（形态合规） |
| **M3** | **幅度** | 修正的绝对大小 | 水平 / 取变化 | ❌ S≤0.78 |
| **M4** | **分歧度收敛** | 分析师意见是否在收敛 | `subtract(ts_mean(短), ts_mean(长))` | ❌ 17 字段全灭 |
| **M5** | **水平偏离** | 预期相对自身历史的高低 | `ts_av_diff(bf, d)` | ❌ |
| **M6** | **价值收益率** | 基本面/市值 | `divide(基本面, cap)` | ❌ 最高 S0.89 |
| **M7** | **规模化改善** | ΔROA、ΔCFO/资产、资产增长 | `divide(ts_delta(bf,252), bf(atq))` | ❌ S≤0.60 |
| **M8** | **PEAD / 盈利意外** | 财报后漂移 | 事件门控 `trade_when` | ❌ S1.03 但必带 CW |
| **M9** | **形态相似度过延伸** | 近期形态相似度 − 长期基线 | `subtract(bf60, bf120)` | ❌ S≤0.46 |
| **M10** | **回归残差** | "A 中 B 解释不了的部分" | `ts_regression(log A, log B, d, rettype=0)` | ❌ 比 `divide` 更差 |
| **M11** | **预期变化水平（模型）** | 同上 M1，字段来自模型数据集 | 同 M1 | ✅ **第二成功族** |

**结论：11 个机制里只有 M1 有效，且它在两个不同 category（MODEL / ANALYST）各成一例。**
机制之间的差别对结果的解释力**远小于**字段本身的差别 —— 见第三节。

## 二、字段类型 → 机制 搭配表（可执行）

### ✅ 值得做

| 字段特征 | 识别方式 | 配什么机制 | 框架 | 实证 |
|---|---|---|---|---|
| **已标准化的"变化率"** | 名字含 `change`，值域是百分比 | **M1 水平+双窗** | 轻框架（`rank` + 单桶轴） | `eps_y1_estimate_change_3mo` → **S1.65/F1.47/0失败**；`mean_estimate_change_pct_f12m_earnings_14d_4` → **S1.75** |
| ↑ 的**同族兄弟** | 同前缀不同期限（7d/14d/30d/60d） | 同 M1，但**必须逐字段重测** | 同上 | 只有 `_14d_4` 成立；`7d_4/30d_5/60d_4` 最高 S1.19 |

### ❌ 见形态即可判死（不必再调参）

| 字段特征 | 识别方式 | 症状 | 本会话出现次数 |
|---|---|---|---|
| **计数 / 事件类** | 名字含 `num` / `count` / `surprisenum` / `raisednum` | **2Y 有信号（1.3~1.7）、S 极低（≈0）** | **5 次独立出现** |
| 原理解释 | — | 信号只在近 2 年存在、全期平；而 `LOW_SHARPE` 卡全期 | — |

### 🚫 不能当信号的字段（只能当轴或分母）

| 类型 | 例子 | 正确用法 |
|---|---|---|
| **PV 元字段** | `close`/`vwap`/`volume`/`adv20`/`returns`/`cap` | 作**分母**（价值收益率）或**分组轴**；**单独作信号 prod 必高**（平台 sector 3749 / industry 3251 / returns 683 / close 577 alphas） |
| **GROUP 型字段** | `pv30` 的 `factor*_group*_top800`、`pv29` 的 `sta1_*`、`country`/`currency`/`exchange` | 只能作 `group_neutralize` 的**轴**，不能进 `rank()`/`ts_mean()` |
| **ISO 货币代码** | `fnd6_*_curcd` | 无信号（cov=1 但纯标签） |

## 三、框架选择：轴层数是**逐字段搜索**的维度

**这是本会话最有价值的方法论产出。**

| 信号性质 | 判据（1 批 5 条即可测出） | 该用 |
|---|---|---|
| **宽信号** | `S(4轴) > S(0轴)` | 重框架（4 轴：图×2 + 行业 + 桶） |
| **脆信号** | `S(0轴) − S(4轴) > 0.3` | 轻框架（`rank` + 仅桶轴，1 轴） |

**实证（同一字段 `mean_estimate_change_pct_f12m_ebitda_14d_4`）**：

| 轴层数 | S | 说明 |
|---|---:|---|
| 0 轴（裸 `rank`） | **1.41** | 脆信号的真实峰值 |
| 1 轴（仅桶） | **1.41** | 同上 |
| 2 轴 | 1.14~1.34 | 开始被削 |
| 4 轴 | **0.82** | 被重锤砸没 |

**对照组（同数据集）**：`_earnings_14d_4` 裸 `rank` 历史单信号最好 1.57 → 加 4 轴 **1.75**（**宽信号，轴是正操作**）。

> **⇒ 默认套 4 轴会系统性错杀脆信号** —— 这很可能是本会话大量"字段没信号"误判的根源。

## 四、窗长与桶（次要旋钮，但有用）

| 旋钮 | 结论 | 证据 |
|---|---|---|
| **信号窗**（M1 的双窗） | **`w1=1 / w2=210` 最优** | 在 ANALYST（W118）与 MODEL 式框架（W140）**两次独立复现** |
| 单窗 vs 双窗 | **双窗抬 2Y、单窗保 S** | 二者是**正交的两个旋钮**，可分开利用 |
| 桶粒度 | **0.05** 最优（0.02 过细、0.06~0.10 偏粗） | gran 扫描 |
| 桶基准 | **必须用信号自身**的慢分量（`ts_mean(bf,252)`） | 换兄弟字段全劣化（S1.54→1.40~1.44） |
| `decay` | **4**（ANALYST 族）；8（MODEL 基准字段） | 逐族实测 |

## 五、S ↔ 2Y 跷跷板（本会话最顽固的结构约束）

| 操作 | ΔS | Δ2Y |
|---|---:|---:|
| 加轴（0→4 轴） | **−0.59** | **+0.46** |
| 双窗（单→双） | 小 | **+0.5** |
| 图轴换 `group_rank` | +0.08 | −0.23 |
| `quantile(driver=uniform)` | +0.04 | −0.29 |
| **短腿窗缩到 1~3** | **+0.03** | **+0.05** ← **唯一同向** |

**⇒ 破闸的正确顺序**：先用**双窗**把 2Y 顶到线上，再用**轻轴**把 S 保住；**不要**指望单一旋钮同时解决两者。

## 六、一眼可用的决策流程

```
1. 这个字段是「已标准化的变化率」吗？（名字含 change，值域是 %）
   ├─ 否 → 先跑「轻框架探针」rank(ts_mean(bf,5)) 1 批
   │        ├─ S ≥ 1.2  → 是宽/中信号 → 进 2
   │        ├─ 2Y ≥ 1.3 且 S ≤ 0.3 → 「计数/事件类」⇒ 判死，停
   │        └─ 其余 → 弱信号 ⇒ 判死，停
   └─ 是 → 进 2

2. 轴深扫描（0/1/2/3/4 轴，5 条）
   ├─ S(4轴) > S(0轴) → 宽信号 → 重框架
   └─ S(0轴) − S(4轴) > 0.3 → 脆信号 → 轻框架（1 轴桶）

3. 用「双窗(1,210) × 上一步选定的轴深」组合，跑一批
   → 若 S ≥ 1.58 且 2Y ≥ 1.58 → 过闸
   → 若 S 缺 → 缩短长腿窗；若 2Y 缺 → 加回一层轴

4. 全不过 → 换字段，**不要**在同一个字段上继续换框架
   （本会话已证：换框架的增益 ≤ 0.3，换字段的增益 0.6~1.5）
```

## 七、一句话总结

> **字段的选择权重 ≫ 机制的选择权重 ≫ 框架的选择权重。**
>
> 本会话 11 个机制、375 次测试，最后只从 **2 个"标准化变化率"字段**里挖出 2 颗 alpha。
> 机制之间差 ±0.3，字段之间差 0.6~1.5。
> **所以正确的工作流是：先用廉价探针筛字段，再谈配什么机制、用什么框架。**
