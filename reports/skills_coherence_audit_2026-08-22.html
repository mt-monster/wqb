七、优化建议（按优先级）

第一批：P1 必改（执行层）

  1. 统一 MCP 命名：选择单一权威前缀（建议保留 skill 广泛使用的 mcp__wq-brain-http__* 或迁移到 wq-brain-stdio），在项目根 .mcp.json 注册该服务（当前只有 wqb-db），并同步 AGENTS.md 的“wqb-mcp”表述。三个来源取一，全链路一致。
  2. 修复激活目录与 zip 的同步：以 ~/.workbuddy/skills/ 为单一事实源，重新出包覆盖 .workbuddy/skills/brain.zip.zip 与 .qoder-cn/skills/wq-backtest-monitor.zip（后者目前只含 3 个示例，明显不完整），确保 INDEX.md 同时进入两侧。
  3. 退役依赖收口：submit-alpha / backtest-monitor 中指向已删目录的脚本引用改为“走 MCP 工具”或删除；selfcorrQuick / judge 的 .qoder/skills/ 路径改为环境敏感变量或相对根（如 %~dp0 / $PSScriptRoot）。

第二批：P2 口径统一

  1. 在 INDEX.md 闸门阶梯增加逐指标、逐 skill 的闸线归属表（内部严线/廉价闸/平台硬线），每根 skill 只引用一个权威入口（如 how-to-pass-AlphaTest 为唯一阈值源），消灭 TVR/Margin/SELF_CORR 的漂移。
  2. 将 ppa-mining & dataset_health_check 的绝对阈值降级为 score_datasets 软评分前的预处理归一，统一到分位 tier 判据，保留绝对阈值仅作兜底报错。

第三批：P3 架构优化

  1. 明确 brain-alpha-orchestrator 与 brain-deepExplore 的关系：要么声明 orchestrator 为 WorkBuddy 侧的上层封装（或在 L-INT 层并列标注），要么将 PPA/combo 路径收回主链，避免双编排触发歧义。
  2. 新 skill 严格执行 wq-brain-<功能> 前缀；存量 brain-*/wqb-* 在 INDEX 标注“兼容旧名”而非继续新增。
  3. 建立一键自检脚本（如 tools/skill_audit.py）：校验 ① 每 SKILL 引用的脚本存在性 ② MCP 前缀是否注册 ③ INDEX.md 唯一性 ④ 嵌套副本权威引用 ⑤ 阈值闸线字面量扫描，纳入 CI，防止下次重构再次漂移。

八、结论

总体评价：主干逻辑连贯、分层清晰，但存在“文档-配置-执行”三层的局部脱节。

  • ✅ 主链 S-PRE→S6 与三角分工（where/what/how）、Artifact 流转契约、五槽填槽模式等 方法论层面连贯性良好；2026-08-15 的重构（INDEX.md / campaign-matrix / 优化器两模式 / 嵌套副本权威声明）基本落地。
  • ❌ 最需要立即修的是 执行层：MCP 前缀三处命名不一致 + 项目根未注册 WQ 工具，可能导致 skill 规划正确但实际回测/提交无法调起；其次是激活环境与 zip 归档不同步、部分依赖脚本已退役。
  • ⚠️ 口径层需统一闸线归属（TVR/Margin/SELF_CORR）与健康检查判据。

建议先落地第一批 3 项（MCP 命名统一、副本同步、退役依赖收口），再用第 8 项自检脚本固化，防止漂移复发。
