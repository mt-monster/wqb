## §10 prod 槽被外部会话抢占的实证

本机只有一个 MCP 服务进程（pid 97924 = `world-quant-brain-mcp/main.py`），所有会话共享它持有的 `logs/_dblock/correlation.lock.json`。实测该 token 的 tag 显示持有者是**另一个会话的 IND 战役**：

```
{"owner":"97924@win","pid":97924,"tag":"corr:get_production_correlation(rKRO6eR8)","at":1793776823}
```

同机还有 4 个 IND 战役进程（`ind_runner.py --datasets fundamental17,fundamental23,fundamental94` + `ind_campaign`）在跑，它们持续抢占账号级 prod 单并发槽，我方调用全部 fail-fast 返回 `correlation_busy`。

**结论**：prod 读数不可按需获取，只能长时间低频重试等窗口。`zq38KdX1` 的 0.7856 是在一次偶然抢到槽时拿到的（elapsed 60.6s、attempts 44）。
