### W1 执行层失败（7/10）：`unitHandling=VERIFY` 禁给带量纲字段加标量

平台报错原文（逐条一致）：

```
Incompatible unit for input of "add" at index 1,
expected "Unit[CSPrice:1]" (或 "Unit[CSShare:1]"), found "Unit[]"
```

**根因**：我在分母写了 `+1` 防除零。`market_value_*` / `quantity_*` / `aggregate_*` 带 `CSPrice` / `CSShare` 量纲，
而常数 `1` 无量纲 ⇒ 量纲校验直接拒绝。家数字段（`count_*`）是 `Unit[]`，所以 W1-02 / 06 / 08 三条**恰好通过**。

**修复协议（后续所有波次强制）**：
1. **禁止**给任何带量纲字段加/减标量。
2. 防除零改用 `divide(a, b)` 直接除（0/0 由平台给 NaN，`nanHandling=OFF` 下自动 0 权重，
   经济上等价于「无流量 = 无信号」，比 +1 更正确）。
3. 若必须给常数，只能出现在**分子分母同量纲相除之后**（此时已无量纲）。
4. 提交前用 `preflight_expressions` 只能查字段存在性，**查不出量纲**；量纲只能靠人工审。

**为什么 `vR1pNEYa` 与 NBER 16591 不一致（诊断，不是放弃理由）**：
它的分母是 `ts_delay(holders, 63)`，而机构持股数是**季度阶梯** ⇒ 63 日差分在多数交易日**恰好为 0**
（两次披露之间没有变化），只有披露日附近才有非零值。结果是「大部分天数信号=0，少数天数跳变」，
`group_rank` 后在 0 附近大量并列 ⇒ 排序退化成噪声。
⇒ **正确修法**：分母锚用 `ts_mean(holders, 72)` 平滑（论坛 A1 的核心发现），并把差分窗口拉到 ≥126 日以跨过两个披露周期。
这正是 W2 采用 `divide(buyers, ts_mean(holders,72))` 的依据。
