### 字段结构（12 指标 × 3 时点）

| 后缀 | 语义 | 用途 |
|---|---|---|
| `_value` | **当前**预测值 | 水平 |
| `_prevalue` | **修正前**的预测值 | **单事件修正 = value − prevalue** |
| `_lastactvalue` | 上次已公布实际值 | 隐含增长 = value − lastact |

12 指标：eps / epsr / ebitda / roe / sales / dps / netprofit / netdebt / fcfps / tbvps / csh / operatingprofit。另有各指标 `_coveredby`（覆盖制式，字符串型，不可用）与 `_lastactccy`/货币码（噪声，跳过）。

## 二、机械定义

```
V(m)   = vec_avg(anl44_2_<m>_value)
Pv(m)  = vec_avg(anl44_2_<m>_prevalue)
REV(m) = (V − Pv) / (|V| + |Pv|)          # 单事件修正，无量纲有界 ∈ [−1,1]
CUM(m,k) = ts_zscore(ts_delta(V(m), k), 252)   # 累积 k 日修正（等价 eps_y1_estimate_change_3mo）
```

**为什么用 `(a−b)/(|a|+|b|)` 而不是 `(a−b)/|b|`**：EPS/净利润/ROE 的预测值可能在 0 附近，`|b|` 作分母会爆炸（ROE 探针实测换手 **161.6%** 就是分母病）。有界相对差无此问题。

## 三、原子探针批（6 条，2–5 算子）

| 探针 | 机制 | Sharpe | 换手 | Fitness |
|---|---|---:|---:|---:|
| A1 | **EPS 单事件修正** | **0.69** | 49.0% | 0.23 |
| A4 | **净利润单事件修正** | **0.52** | 62.3% | 0.14 |
| A2 | EBITDA 单事件修正 | 0.40 | 62.1% | 0.10 |
| A3 | ROE 单事件修正 | 0.35 | **161.6%** | 0.07 |
| A6 | EPS 预测量 vs 上次实际（隐含增长） | −0.11 | 31.6% | −0.02 |
| A5 | 营收单事件修正 | −0.31 | 48.9% | −0.07 |

### 【判据一】底线指标 > 中线指标（机制成立的正向证据）

EPS 0.69 > 净利润 0.52 > EBITDA 0.40 > 营收 **−0.31**，**单调递减且营收翻负**。
⇒ 经济学上正确：越靠近**每股底线**的修正越直接映射到价格；营收修正需要经过利润率假设才能传导，噪声更大且方向可反转。**这不是噪声排列，是机制信号。**

### 【判据二】机制是「预测 vs 上次预测」，不是「预测 vs 实际」

`REV = value − prevalue` → 0.69；`value − lastactvalue`（隐含增长）→ **−0.11**。
⇒ 修正漂移（Gleason-Lee 2003）吃的是**修正这个动作本身**，而不是预测相对实际的乐观程度。用隐含增长当信号是常见误配。

### 【判据三】ROE 之类的「比率型指标」必须用有界相对差

ROE 修正若用 `(v−p)/|p|` 会因 p≈0 爆炸 → 实测换手 **161.6%**（平台 HIGH_TURNOVER 线 70%，超 2.3 倍），Sharpe 也被稀释到 0.35。改用 `(|v|+|p|)` 作分母后正式波 H 版换手降到 **7.69%**。

## 五、结论与方法论收获

### 5.1 【★★★★】单事件修正有信号，但换手不可用；平滑后换手可用但信号被抹平

| eps 修正的不同加工 | Sharpe | 换手 |
|---|---:|---:|
| 裸 `rank(REV)`（探针 A1） | **0.69** | 49.0% |
| `rank(ts_mean(REV,22))` + CUM 融合（A） | 0.19 | 53.9% |
| `ts_mean(sign(REV),66)` 方向一致性（F） | 0.44 | **4.9%** |

⇒ 这是一个**换手-信号强权衡**：原始事件修正的 0.69 里有一大块来自高频抖动，压到合规换手（<70%，实际要压到 10% 才有 fitness）后只剩 0.44。
**fitness 最好的 F（0.20）远低于 LOW_FITNESS 1.0 线。**

### 5.2 【★★★★★】第三次独立验证：水平型/模型类信号加差分必毁

| 数据集 | 纯水平/原始 | 加差分后 |
|---|---|---|
| CE 电话会情绪 | 比率 1.90 | 变化量 0.44 |
| model264 ebitda | `rank(R)` **+0.41** | +NTM 变化 −0.44 |
| **analyst44 eps** | **裸 REV 0.69** | +CUM(ts_delta) **0.19** |

⇒ **规律已三次独立成立**：预期/概率类水平信号，`ts_delta` / `ts_av_diff` / 二阶差分是毒药。**别把“更新”误当“动量”。**

### 5.3 【★★★】三指标共识在本族无增益

B（eps+净利润+EBITDA 累积共识）= −0.12，低于任一单指标探针（0.69/0.52/0.40）。三条腿同源（同一批分析师的同一份模型），平均只会稀释最强的那条。
⇒ 与 model264 的「同一模型输出的不同指标不是多样化来源」完全一致。**跨指标平均 ≠ 分散化。**

### 5.4 【★★】coverage 0.32–0.79 是硬伤但不是致命伤

E（dps, cov 0.68）与 H（roe, cov 0.655）都能正常出值，低覆盖字段（tbvps 0.41 / csh 0.369 / 营业利润 0.323）在本轮重派批里验证。但 TOP500 只剩 ~330 只可交易票，横截面已经很薄。

## 六、踩坑

1. **全 VECTOR**：任何字段直接进表达式都会报错，必须先 `vec_avg`。且按既有纪律，event 型 VECTOR 禁元素级 `power/multiply/abs/sign`，只能在聚合后使用。
2. **`_coveredby` 是字符串型覆盖制式**，`_lastactccy`/各种 `_currency_code_*` 是货币码 —— 都要显式排除。
3. **`ts_delay` 不在平台算子表里**，累积修正只能用 `ts_delta`（等价于 x − ts_delay(x,d)）。
4. **平台通用 ERROR 而非语法错**：I/J/K/L 四条预检全过却返回 `There was an error while running the simulation`，重派后重新计算 ⇒ 属平台瞬时故障，遇此先重派再怀疑表达式。
5. **`rank(class)` 类离散信号的换手陷阱** 已在 model264 记录（38%），本数据集不涉及但同理：事件型信号的裸几何换手普遍 30–160%，直接提交必挂 HIGH_TURNOVER。

## 七、判定（初稿，待 I/J/K/L 回收）

**analyst44 = 机制真实但强度不足。** 最好 0.69（裸 EPS 修正，换手 49%），合规换手下最好 0.44。距 LOW_SHARPE 1.58 差 2.3 倍、距 LOW_FITNESS 1.0 差 2.3 倍。
该数据集属 **ANALYST 塔 ∉ 禁混集合**，因此**可以与非禁混集合的数据集自由组腿（不限量）**——这是它相对 model264 的最大战略价值。下一步应作为**门控腿/条件腿**与 shortinterest（另一已验证塔）组合，而不是继续单塔 ATOM 加固。
