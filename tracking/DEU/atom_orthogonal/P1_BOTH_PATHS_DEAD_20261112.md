## 三、BE175 的单位闸踩坑（7/10 臂 WARNING）

错误：`Incompatible unit for input of "add" at index 2, expected "Unit[CSShare:1]", found "Unit[]"`

**根因**：`total_buy_shares` / `total_sell_shares` / `avg_buy_shares` 等字段是 **`Unit[CSShare]`（股数单位）**，
而 `HHI` / `DI` / `SV1`（经 group_rank 后）是 **`Unit[]`（无量纲）**。直接 `add()` 单位不兼容。

**修法**：任何股数/金额字段必须先 `group_rank` 包裹归一到无量纲，再参与算术。
（本例里 `TB` 定义确实用了 group_rank，但表达式里我直接引用了裸字段名——模板拼接时把包裹层丢了。）

⇒ 这是本项目第三次踩单位闸（前两次：`bucket` 作分组轴、`ts_zscore→ts_av_diff`）。
⇒ **纪律：派发前对每条表达式检查「算术算子两侧的单位族是否一致」**，尤其股数（CSShare）/金额（CSPrice）字段。

## 四、结论

**ATOM（单数据集）在 DEU insiders 上不可行**：两个数据集单集上限分别是 1.30 与 0.93，都低于 1.58。

机理（已写入记忆）：ATOM 要求单 dataset，而单 dataset 内字段往往同源（同一事件的派生量），
跨字段叠加必然稀释 ⇒ **ATOM 天然限制了可叠加的信息量**。

这与目标「优先 ATOM」存在结构性冲突，不是调参能解决的。
