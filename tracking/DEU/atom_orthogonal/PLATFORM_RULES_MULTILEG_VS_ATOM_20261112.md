# 平台官方 vs 论坛：对「多腿相加 / 混信号」的惩罚与硬限

日期：2026-11-12　方法：读论坛权威帖 + 9 颗 alpha 实测复核

## 结论速览

| 问题 | 答案 |
|---|---|
| 平台对多腿相加有**硬性限制**吗？ | **没有。** RA 唯一硬限是 64 算子 |
| 有**惩罚**吗？ | **没有直接惩罚。** 只有间接的软代价 |
| 混信号会被拒提交吗？ | **不会。** 是分类标记，不是违规 |
| 那为什么内部要禁？ | 防过拟合 / 降池内相关性 / 保 VF。属**内部纪律**，非平台规则 |
| ATOM 有什么平台红利？ | **IS_LADDER 检查直接不出现**（实测 5/5 无此项）|

## 一、平台官方口径（论坛 v201《BRAIN 平台上的四类Alpha》）

> **Regular Alpha（RA）**：表达式内的操作符和数据字段数量只要不超过 **64 个**就可以提交；
> 几乎**没有其他限制**，是最自由的表达方式；需要通过所有的 Alpha 检测标准。
>
> **ATOM Alpha** 判定标准：所有使用的数据字段必须来自**同一个数据集**；
> 常见的 group 字段如 industry、country 等是**豁免字段**，不计入数据集数量限制；
> 特别检测机制：**放松了 IS Ladder Testing 要求，仅要求通过最近两年的 2-Year Sharpe 检测**。

⇒ **平台层面，「两条独立信号腿相加」不违规、不惩罚。** 唯一硬限是 64 算子（与我方实测吻合）。

## 二、论坛共识：混信号是「分类标记」，不是违规（v122，24 条评论）

> 新人问：混信号是不能提交吗？
> **答：完全可以提交，放心大胆地交！**「混信号」并不是违规信号，
> 它只是系统对 Alpha 的一种**分类标记**。

> 新人问：那混信号的后果是什么？
> **答：** ① 它不会被标记为 ATOM（若官方活动强制要求 Single Data 就不算数）；
> ② 涉及多个数据源时，可能因某个数据集太热门导致 **PC 偏高**，或 OS/combine 不稳定。

### 但有真实的长期代价（v1《新人避坑指南》）

> 之前账号升到 GOLD 时交了不少混信号 alpha，导致后来 IQC 比赛期间**池子里的字段相关性过高**，
> 就很难出低相关性的 alpha 了，所以 IQC 期间能不混信号就不混信号。

⇒ 这正是内部闸5 的真正理由：**不是平台罚你，是把自己的池子搞脏了，后面更难做。**

## 四、补充：PPAC 是门槛更低的另一条路

| 项 | RA | PPAC |
|---|---|---|
| 字段数 | 无限制 | **≤3** |
| 算子数 | **≤64** | **≤8** |
| Sharpe | 按区域阈值（DEU 1.58）| **> 1**（低得多）|
| Fitness | 要求 | **不要求** |
| IS Ladder | 有（ATOM 除外）| **无** |
| Sub-Universe | 有 | 有 |
| 自相关 | self + prod | pool 内 <50% 或领先 10% |
| 数量限制 | 每日常规配额 | PPA+ATOM 双标签**无限制**；纯 PPA 每日 1 / 每区月 10 |

2025-11 起 PPA 额外要求：中性化必须是 RAM / STATISTICAL / CROWDING / FAST / SLOW / SLOW_AND_FAST 之一。

⇒ 若目标是「尽快出货」，PPAC+ATOM 双标签路线门槛显著低于 RA。

## 五、对我们的行动含义

1. **内部闸5 保留**（它防的是池子污染与过拟合，是真代价），但要**知道它是内部纪律而非平台规则**——
   当用户明确要求交付数量时，可以说清「这些件平台可提交，只是违反我方混信号纪律」，由用户裁决。
2. **构造第一问改为「能不能只用同一 dataset」**——ATOM 直接省掉 IS_LADDER 一道闸。
3. **group 字段豁免**：`sector`/`industry`/`market` 不计入数据集数，所以「单数据集 + sector 中性化」仍是 ATOM。
4. **塔数 ≤2 才有点塔收益**：v122 提到「一个 alpha 最多只能有两个字段才能点塔，多出的无法点塔」，
   与我方实测「三塔 eff=0」一致。
