# BRAIN 数据特征工程工作流

**目的**：将 BRAIN 数据集字段自动转化为深入、有意义的特征工程思路。

**思维模式详解**：参见 `reference.md`（特征工程理念）。
**实现示例**：参见 `examples.md`（案例研究）。

## 输入要求

### 必填参数：
- **data_category**：数据集类别（如 "fundamental"、"analyst"、"news"、"model"）
- **delay**：数据延迟设置（0 或 1）
- **region**：市场区域（如 "USA"、"EUR"、"ASI"）

### 可选参数：
- **universe**：交易域（默认："TOP3000"）
- **dataset_id**：具体数据集 ID（若已知，跳过发现阶段）

## 工作流概览

### 第 0 步：字段透明度分档（2026-09-01 精简，强制前置）

按数据集字段语义透明度分档，决定分析深度（避免对自解释字段集浪费分析轮次）：

| 档位 | 判定标准（满足其一） | 分析深度 |
|---|---|---|
| **透明集** | fundamental/analyst/earnings/insiders/shortinterest 类且字段名含标准财务词汇（eps/revenue/ebitda/estimate/revision/holder 等）；或字段描述覆盖率 ≥80% 且描述均值 >5 词 | 跳过第 3 步 8 问深度分析，直接：字段画像（第 2 步）→ 预处理决策 → 白名单（第 4-6 步照常入库） |
| **黑盒集** | other*/model*/ai_*/ml_* 等评分型/投影型字段集；或字段名无语义（如 q1s3_x87）；或描述覆盖率 <30% | 全量执行第 3 步 8 问分析（黑盒字段无经济语义则 GEM 绑定池失控） |
| **半透明** | 介于两者之间（如 pv/risk 系） | 第 3 步只做 B 组问题驱动的快速版（1/2/7 三问：不变量/变化/相对位置） |

分档依据：2026-09-01 价值审计——8 问分析对透明集边际价值低（字段名自解释，103 个 s1 键中透明集的分析内容高度模板化），对黑盒集（other455 类 1500 无语义字段）是刚需。

### 第 1 步：数据集发现
**自主动作：**
- 以参数（category, delay, region, universe）调用 `mcp__wq-brain-http__get_datasets`
- 若提供了 dataset_id：校验并使用它
- 若未提供 dataset_id：基于元数据分析选择最相关的数据集
- **S0 白名单校验（S0→S1 衔接，强制）**：`mcp__wqb-db__get_ledger_key(region, "s0_whitelist")` 命中时，锁定数据集必须在白名单 `datasets` 内（不在则报出冲突并停，交回编排器，勿自行越白名单分析）；未命中（无战役目录的临时分析）跳过校验
- **输出**：锁定用于分析的数据集 ID

### 第 2 步：字段提取与解构
**自主动作：**
- 对所选数据集调用 `mcp__wq-brain-http__get_datafields`
- 对每个字段提取：id、description、dataType、更新频率、覆盖率
- **解构每个字段的含义**：
  * 测的是什么？（实体/概念）
  * 怎么测的？（采集/计算方法）
  * 时间维度？（瞬时、累计、变化率）
  * 业务背景？（该字段为何存在？）
  * 生成逻辑？（可靠性考量）
- **建立字段画像**：结构化理解每个字段的本质

### 第 3 步：自主思考与分析
**本 skill 基于收集到的信息做深入分析：**

**A. 字段关系映射**
- 分析字段间的逻辑联系
- 识别：独立字段、相关字段、互补字段
- 勾勒数据集讲述的"故事"
- **关键问题**：这些字段暗示了哪些关系？

**B. 问题驱动的特征生成（内部过程）**
本 skill 向自己提出以下问题并生成特征概念：

1. **"什么是不变的？"** → 寻找不变量
   - 哪些字段或组合相对恒定？
   - 什么样的稳定性度量有意义？

2. **"什么在变化？"** → 分析变化模式
   - 变化率、加速度、波动率
   - 趋势与噪声的分离

3. **"什么是异常的？"** → 识别偏离
   - 离群点、异常模式、偏离常态
   - 偏离幅度与显著性

4. **"什么被组合在一起？"** → 考察交互
   - 字段之间如何相互作用、放大或抵消
   - 合成产生新含义

5. **"什么是结构性的？"** → 研究构成
   - 组成成分、比例关系
   - 结构随时间的演变

6. **"什么是累积的？"** → 探索累积效应
   - 随时间累积、衰减效应
   - 数据中的记忆与持续性

7. **"什么是相对的？"** → 做比较
   - 相对定位、排名、归一化
   - 在数据集内的上下文

8. **"什么是本质的？"** → 提炼核心含义
   - 第一性原理思考
   - 剥离假设，直达本质

**C. 特征概念生成**
对每个相关的问题-字段组合：
- 构思回答该问题的特征概念
- 清晰定义概念
- 明确逻辑含义
- 考虑方向性（高/低值代表什么）
- 识别边界条件
- 记录潜在问题/局限

### 第 4 步：特征文档化
**对每个生成的特征概念，记录：**
- **概念名称**：清晰、描述性的名称
- **定义**：一句话定义
- **逻辑含义**：它代表什么现象/概念？
- **为何有意义**：为什么这个特征合理？
- **方向性**：高值与低值的解读
- **边界条件**：极端值指示什么
- **数据需求**：使用哪些字段、有何约束
- **潜在问题**：已知局限或担忧

### 第 5 步：输出生成
**生成结构化 markdown 报告，包括：**

将报告写入 `./output_report/region_delay_datasetID_ideas.md`，格式如下：

> **产物去向（S1→S2 契约）**：本 ideas markdown 是 S2 `brain-makeSomeGem` 的法定输入——经其 `run.py --ideas-file <本文件路径>` 注入后，流水线跳过内部嵌套 S1 重新生成，直接沿用本报告的字段白名单与预处理决策实现表达式；编排器（`wq-brain-ra-pipeline`）在步 4 调用时必须传该参数，否则本 skill 的独立调用成果不会被消费。

1. **数据集理解**
   - 数据集描述与特征
   - 字段清单（数量、类型、更新模式）
   - 关于数据结构的要点观察

2. **字段解构分析**
   - 每个字段：它真正测的是什么、为什么
   - 字段间的逻辑关系
   - 数据讲述的"故事"

3. **按问题类型分类的特征工程建议**

   **3.1 稳定性特征**
   - 度量稳定性/不变性的概念
   - 为什么稳定性在本数据集中重要
   - 实现示例

   **3.2 变化特征**
   - 捕捉变化模式的概念
   - 速率、加速度、波动度量
   - 时间动态

   **3.3 异常特征**
   - 偏离与离群点检测概念
   - 正常 vs 异常的识别
   - 显著性度量

   **3.4 交互特征**
   - 跨字段交互概念
   - 放大、抵消、合成效应
   - 组合意义创造

   **3.5 结构特征**
   - 构成与关系概念
   - 比例分析
   - 结构变化检测

   **3.6 累积特征**
   - 累积与衰减概念
   - 记忆/持续性度量
   - 时间加权效应

   **3.7 相对特征**
   - 比较与归一化概念
   - 排名与分位数度量
   - 上下文相对定位

   **3.8 本质特征**
   - 第一性原理推导的概念
   - 核心含义提取
   - 基础度量

4. **实现考量**
   - 数据质量说明
   - 覆盖率考量
   - 计算复杂度
   - 潜在改进/扩展

5. **进一步探索的关键问题**
   - 哪些方面尚未覆盖？
   - 哪些额外数据会有帮助？
   - 哪些假设应被质疑？


### 第 6 步：台账回写（S1 决策入库，强制）

ideas markdown 落盘后，**必须**把 S1 决策写入 `data/wqb.db` 的 ledger_kv 表（结构化真相源；ideas markdown 仅为可读呈现与 S2 `--ideas-file` 注入路径）。会话内直接调用 MCP upsert：

```
mcp__wqb-db__upsert_ledger_key(
  region="<REGION>",
  key="s1_<DATASET_ID>_d<DELAY>",
  value={
    "dataset": "<DATASET_ID>",
    "region": "<REGION>",
    "delay": <DELAY>,
    "universe": "<UNIVERSE>",
    "ideas_md_path": "<第 5 步写入的 ideas.md 绝对路径>",
    "field_whitelist": ["<字段名>", ...],
    "preprocessing": {"<字段名>": "backfill|winsorize|rank|zscore|ts_event_*", ...},
    "concept_count": <概念数>,
    "source": "standalone",
    "generated_at": "<ISO 时间戳>"
  }
)
```

- key 命名 `s1_<dataset>_d<delay>`（不可用 `_` 前缀，会被 ledger schema 守卫拒绝）；同 (region, dataset, delay) 重跑自动覆盖（upsert 幂等）。
- 战役目录内也可用 toolkit CLI：`campaign.py --campaign-dir <CD> ledger set "s1_<ds>_d<delay>" '<json>'`。
- **S1⇄S2 统一逻辑链（状态机，两个写方、一个记录）**：本 skill（`source="standalone"`）与 S2 自含模式（`brain-makeSomeGem` 内嵌 S1，跑完由 S2 会话回写 `source="s2_nested"`，schema 完全一致）是同一逻辑步骤的两条物理路径，**都收敛到同一 ledger key**。S2 启动判定：`get_ledger_key(region, "s1_<ds>_d<delay>")` 命中且 `ideas_md_path` 可读 → `--ideas-file` 注入（内嵌 S1 不再执行）；未命中 → S2 自含跑并回写。由此：同一 (region, dataset, delay) 的内嵌 S1 至多跑一次，字段白名单/预处理决策以该 ledger 记录为唯一口径，S3 五闸校验与 S6 回写闭环均读此记录，不再存在第二条未入库的决策通道。
- S0 换数据集/换 delay 时，对应 ledger key 由后续 S1 覆盖，无需删除。

## 核心分析原则

1. **从数据本质出发**：从数据真正意味着什么开始，而不是它传统上被用来做什么
2. **自主推理**：本 skill 完成全部思考，无需用户输入
3. **问题驱动**：内部问题库引导特征生成
4. **含义优先于模式**：逻辑含义优先于常规组合
5. **透明性**：在输出中展示推理过程

## 示例输出结构

以数据集 'BEME'（Balance Sheet and Market Data，资产负债表与市场数据）为例，输出将包括：

### 数据集理解
**分析字段**：book_value、market_cap、book_to_market 等
**要点观察**：该数据集将会计账面价值与市场估值进行对比

### 字段解构
- **book_value**：会计对净资产价值的计算（季度、经审计、基于历史成本）
- **market_cap**：市场参与者的估值（连续、前瞻性、受情绪影响）
- **book_to_market**：比较这两种估值视角的比率

### 生成的特征概念

**来自"什么是不变的？"**
- "市场重估稳定性"：book_to_market 的滚动变异系数
- **逻辑**：度量市场观点是稳定还是波动
- **含义**：稳定值说明存在共识，波动值说明存在分歧/不确定性

**来自"什么在变化？"**
- "价值创造 vs 市场重估分解"：分离 book_value 增长与 market_cap 增长
- **逻辑**：区分基本面价值创造与市场情绪变化
- **含义**：是什么在驱动 book_to_market 的变化？

**来自"什么被组合在一起？"**
- "无形价值占比"：(market_cap - book_value) / enterprise_value
- **逻辑**：量化无形价值（品牌、成长等）所占比例
- **含义**：估值中有多少比例未被资产负债表捕捉？

**（后续还有更多基于问题的特征...）**

## 实现说明

### 本 skill 应当：
1. **先分析，后生成**：提出特征前先充分理解数据集
2. **展示推理**：解释每个特征概念为何合理
3. **保持具体**：引用真实字段名及其特征
4. **保持批判**：质疑假设并识别局限
5. **保持创造**：超越传统财务指标

### 本 skill 不应当：
1. **让用户思考**：所有思考都在 skill 内部完成
2. **提供通用模板**：每次分析都应针对具体数据集
3. **依赖传统认知**：挑战传统做法
4. **输出无含义的模式**：每条建议必须有清晰逻辑

## 质量保证

**自查流程：**
- [ ] 所有字段都被分析，而非一带而过
- [ ] 字段含义被理解为超越表面描述
- [ ] 探索了多种问题类型
- [ ] 每个特征都有清晰的逻辑含义
- [ ] 推理显式呈现，而非隐式
- [ ] 局限已被承认
- [ ] 输出针对具体数据集，而非通用

**验证问题：**
- 该分析能帮助他人真正理解数据吗？
- 特征概念是否新颖且有意义？
- 推理过程是否透明？
- 是否避开了传统思维陷阱？
