> 数据集：`sentiment26`（sentiment 塔 / 未点亮）
> 平台事实：USA / TOP3000 / delay 1；字段 33 个，**全部 VECTOR**；基础块覆盖 0.7692，
> 带 `_N` 后缀块覆盖 0.944；aC 1–187（最高 `snt26_totaldomains` 187、`snt26_relpopularity1` 112）。
> 状态：**未判死**（`get_dead_ends(USA)` 无记录）；sentiment 塔未点亮。
> 同塔负证据：`news_sentiment_dl`（max S 0.63）、`ai_news_scores`（max |S| 0.48）、`sentiment21`（max |S| 0.58）、
> `mmp_nlp_sentiment`（24 回测 0 ra_clean）、`news_sentiment_transfer`（2 批 16 条 max S 0.50，已封存）。
> **但本集不是文本情绪**：它是 Cisco Umbrella DNS 解析热度，属「注意力/关注度」代理，机制与文本分数族不同。

## 1. 字段画像

### 1.1 频次与覆盖

- **观测频率**：日频（描述均以 "on the observation date" 表述；`snt26_wq_pit` 为 PIT 时间戳字段）。
- **覆盖两档**：基础字段 0.7692（约 17 个）与 `_N` 后缀字段 0.944（约 13 个）。
  两档**不是不同概念**，而是同族的另一套聚合/回填版本（描述逐字相似，如 `relpopularity1` vs `relpopularity1_6`）。
  低覆盖带（0.77）仍高于本区常用的 0.4 弃用线，**但低于 0.9**，裸用会有覆盖缺口。
- **MCP 的 sharpe 过滤**：本次 `get_datafields` 返回 `sharpe_filter_applied=true / removed=3`，
  即平台侧还有 3 个字段被本地过滤隐藏；本批不依赖它们。

### 1.2 字段 5 家族归类（按 `brain-alpha-research-news-sentiment` 分类器口径）

| 家族 | 字段 | 说明 |
|---|---|---|
| **attention（关注度）** | `relpopularity1` / `_6`、`relpopularity08` / `_11`、`totaldomains` / `_5`、`totalcountrydomains_13`、`rank` | 解析热度广度：域名数、按 1/rank 或 1/rank^0.8 加权的复合关注度 |
| **direction（水平/方向）** | `avgranking` / `_7`、`topranking` / `_10`、`top{10,25,50,75}pctranking` 及 `…avg` 系列 | **排名越低越热门**，是"热度水平"而非情绪方向；方向语义需在构造中取负 |
| **dispersion（分布形状）** | `kurtosis` / `_15`、`skewness_9` | 排名分布的形状（尾部厚薄/偏斜） |
| ~~event_type~~ | — | 无事件码 |
| ~~peer_context~~ | — | 无同侪预聚合 |
| 元数据（非信号） | `dltcc`（国家码 TLD，类目）、`wq_pit` / `wq_pit_16`（时间戳） | **不得作信号**（S1 语义剔除） |

**覆盖率陷阱**：`kurtosis`（0.7692）与 `skewness_9`（0.8797）是分布形状字段，但同族只有这两档；
`skewness` 没有 0.77 覆盖的基版，`kurtosis` 的 0.944 版是 `_15`。选字段时优先用同覆盖率的一对，
否则两档覆盖混用会在横截面上造成"有的股票用 A 版本、有的用 B 版本"的隐式分组。

### 1.4 VECTOR 处理约束（必须遵守）

- 所有字段为 VECTOR，**必须先 `vec_*` 聚合再进标量算子**（`event-vector-vec-rank` 的硬规则）。
- 可用聚合：`vec_avg` / `vec_sum` / `vec_count` / `vec_min` / `vec_max` / `vec_stddev` / `vec_range`。
- `vec_sum(relpopularity1)` 才是描述里的复合关注度；`vec_avg(rank)` 才是均值排名。
- `vec_count(snt26_rank)` = 该发行人当日映射到的域名数（广度计数）；
  注意空向量可能返回 0 而非 NaN ⇒ 若用它做主信号，需与 `vec_avg` 交叉校验是否被"0 值"污染。

## 2. 适用模板（机制先验）

文献锚点：

1. **Da, Engelberg & Gao (2011), In Search of Attention**：Google 搜索量代理散户关注度，
   **关注度异常上升 → 短期正收益、随后反转**。DNS 热度是同构代理（解析量 ≈ 访问热度）。
2. **Barber & Odean (2008)**：注意力驱动的买入造成短期过度定价 ⇒ 水平高/关注暴涨后**负**收益。
3. **Tetlock (2007) / Baker & Wurgler (2006)**：情绪/注意力只在**条件**与**变化**上有信息，裸水平易被定价。

⇒ 本集不测"裸水平"（会退化成 size/科技股 beta），只测**自归一后的关注度意外、变化、广度增长与集中度**：

| 模板 | 构造 | 机制 |
|---|---|---|
| T1 关注度意外（水平自归一） | `ts_zscore(vec_sum(relpopularity1), 252)`，正/负两向 | 相对自身历史的热度异常 → 短期动量或过度定价反转 |
| T2 关注度增长 | `ts_av_diff(vec_sum(relpopularity1), 22)`，正/负两向 | ASVI 式关注脉冲 |
| T3 广度增长 | `ts_zscore(vec_count(snt26_rank), 252)` | 域名覆盖扩张 = 业务/营销扩张的代理 |
| T4 集中度 | `vec_stddev(rank) / (vec_avg(rank)+1)` 的 ts_zscore，取负 | 热度集中在头部域名 = 单一产品依赖（脆弱） |
| T5 头部热度改善 | `-ts_av_diff(vec_min(rank), 22)` | 最强域名排名改善 → 关注度上升 |
| T6 稳健性 | `relpopularity08` 的 Δ22 | α 参数敏感性对照 |

标准壳（USA/D1/TOP3000）：`quantile(group_rank(hump(ts_backfill(winsorize(<SIG>, std=4), 252), hump=0.01), industry))`。

## 5. 风险与预判

- **规模 beta 风险（最高）**：热度水平与公司规模强相关；本批全部构造都做了自归一或差分，
  若仍出现 risk-neut <0.3，说明 DNS 热度本质是风格代理，立即判死。
- **覆盖率 0.77**：低于 0.9，须保留 `ts_backfill(252)`；若出现 CW 集中，改 `group_backfill` 或换 `_N` 高覆盖版。
- **空向量→0 污染**：`vec_count` 需与 `vec_avg` 互校（见 §1.4）。
- **同塔判死阴影**：文本情绪族 5 次失败不构成对本集的判据（不同机制），但若本批全 <1.0，
  sentiment 塔只应继续试 `sentiment26` 的非文本变体或换塔，不得回头重测文本分数族。
