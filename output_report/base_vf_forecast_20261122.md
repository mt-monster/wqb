# 每日提交件的 base 预估与 VF 提交前后（2026-11-22）

工具：`tools/gates/base_forecast.py`｜标定样本：本账户 91 个「有提交且有 base 到账」的交易日
账户状态：**VF 0.73｜Osmosis Rank 0.85｜(1+OS)=1.85**（2026-11-22 实测）

---

## 0 一句话结论

**"按官方公式精确算 base"不成立——平台没公开解析式。** 但可以把问题拆成三层，
其中两层能算，一层只能给区间：

| 层 | 能不能算 | 依据 |
|---|---|---|
| ① 乘数链 `(Theme+Pyramid−1)×(1+OS)` | **能，精确** | 三项全是平台字段（`pyramids[].multiplier` / `submit_verdict.themes[]` / `dailyOsmosisRank`） |
| ② 数量曲线（n → base） | **能，本账户稳健** | 91 天实测，单调 |
| ③ 质量项（PC / Fitness / S）的跨档弹性 | **只能给区间** | 样本内 PC 全落在 0.48–0.83，**0 天 <0.25** ⇒ 社区那个 ×4–5 台阶无法自标定 |
| VF 提交前后 | **方向能算，数值是代理** | 恒等式 `diversity_score=(A/N)×(P/216)×S_H`；`valueFactor` 本体要等平台季度更新 |

## 3 VF 提交前后（11-21 这一批）

窗口取「截至 11-20」= 真前值（当日提交已进窗口，不能拿 11-22 的读数当前值）：

| 项 | 值 |
|---|---|
| 提交前 diversity_score | **0.119586**（N=79，A=41，P=52，S_H=0.9571） |
| 提交后 | **[0.121119, 0.127028]** |
| Δ | **+1.28% ~ +6.22%** |
| ΔP | **+2**（`USA/D1/INSIDERS`、`GBR/D1/IMBALANCE` 均为新开类别） |

⇒ 这两颗都开新塔类 ⇒ 多样性分**必升**（ΔP≥1 的数学结论）。
若 ΔP=0（同质加厚），下界会是 −1.25%（A 不增时 `N/(N+1)`）。

> **口径提醒**：`diversity_score` 是 VF 的**趋势代理**，不是 VF 本体。
> `valueFactor=0.73` 由平台按季度/窗口更新，提交当天不会变；能观测到的是它的先导指标方向。

## 4 用法

```bash
# 每天标定一次（约 1–2 分钟，结果落 cache/，可复用 24h）
python tools/gates/base_forecast.py --calibrate --days 110

# 预测当日已提交件 / 未提交候选
python tools/gates/base_forecast.py --date 2026-11-21
python tools/gates/base_forecast.py --alpha <id1>,<id2>

# 只看 VF 影响（不跑 base）
python tools/gates/base_forecast.py --date 2026-11-21 --vf-only
```

退出码：0 正常｜2 样本不足（<12 天配对）｜3 参数错。

## 5 边界（必须一起读）

1. **不给"精确到分"的报价**：残差 ×1.09 已吃掉小数位，跨档（PC<0.25）连区间都不该外推。
2. **PC<0.25 的台阶未标定**：社区 9 案例里 G（PC .2480 → $9.03）与 H（PC .2085 → $36.40）
   差 4 倍 ⇒ 台阶阈值不在 0.25 整点，位置未知。
3. **theme 倍率不是清单里的 max**：`submit_verdict` 返回的 `themes[]` 是"被检查过的主题"，
   `checks.pass` 含 `MATCHES_THEMES` 才是命中；两者不一致时本工具按保守值算并标 `*`。
4. **`base` 与"提交"是同日口径**（lag=0 拟合优于 lag=1，R² 0.532 vs 更低），
   但这只说明统计关联；平台实际结算口径未公开。
