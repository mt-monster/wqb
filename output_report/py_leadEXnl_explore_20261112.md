## 2 根因（已确认）

**`nan_to_num(nan=0)` 是主因。** 内幕字段覆盖率仅 0.53，`q` 腿有 ~47% 股票为 NaN；
把它们填成 **0** 等于「在 [0,1] 打分体系里给最低分 = 强空」，凭空造出一个「内幕数据缺失」的空头因子，
把真实信号污染掉。改成填 **0.5（rank 中性位）** 后：

- S 0.92 → **1.74**（+0.82）
- F 0.53 → **1.23**
- long 101 → 153（回到与 FASTEXPR 同级的持仓宽度）

已排除：`sector` 整型哨兵（加处理后 PnL 4228226 逐位不变）、`lookback` 70 vs 66（无影响）。

## 3 仍未对齐的部分

| 指标 | FASTEXPR `Jj8qWmlx` | Python `npa95xPq` | 差 |
|---|---|---|---|
| Sharpe | 2.17 | 1.74 | −0.43 |
| Fitness | 1.65 | 1.23 | −0.42 |
| **2Y** | ladder PASS（2.32） | **0.69（FAIL，lim 1.58）** | 大 |
| sub | 1.38 | 1.33 | −0.05 |

**2Y 是最大缺口**：Python 版近两年几乎失效，说明不是简单的尺度问题，而是**信号形状在时间上不一致**。

剩余假设（按可能性）：

1. **`rank` 的归一化基数不同**：平台 `rank` 可能以 universe（TOP500）为分母，而 Python 的 `data.field` 可能覆盖更宽的票池 ⇒ 分布不同、时序稳定性不同。可试 `rank01 = (order + 0.5) / n` 或截断到 `[0.001, 0.999]`。
2. **`ts_mean` 对稀疏序列的实现差异**：平台可能先 forward-fill 再平均，我用 `nanmean`（跳过 nan）。两者在内幕交易稀疏场景下差别很大，且会影响 2Y 稳定性。
3. **两档 est 窗口的有效性**：Python 单腿 e14 = 1.37、2Y 仅 0.24，说明这条腿本身就近两年衰减；FASTEXPR 里它可能被 `q` 或 `e90` 的交互放大，而 Python 没复现这个交互。

## 4 结论与建议

- **Python 通道本身可用**：`operatorCount=null`、正常点塔、字段全 MATRIX 无阻塞，机制已跑通。
- **但当前不能替代 FASTEXPR 交付件**：1.74 / 2Y 0.69 不过闸。FASTEXPR `Jj8qWmlx`（9 ops）仍是唯一可交付版本。
- **继续对齐的最短路径**：先做两条最小对照——Python `rank(close)` vs FASTEXPR `rank(close)`（0.01）、Python `ts_mean(close,22)` vs 0.44。这两条对上后，再调 `q` 腿的 `ts_mean` 实现（试 forward-fill 版），最后看 2Y 是否回到 1.5+。
- **价值判断**：即便对齐成功，收益也只是「六维里 Operators per Alpha 少 9 个」；若对齐成本高于收益，不如把这颗按 9 ops 直接交，把 Python 通道留给**新开候选**（一上手就写 Python 形态）。

### 6.2 q 腿的五种实现（全部实测，都不到 0.90）

| 实现 | S | 说明 |

### 6.3 结论

- **FASTEXPR 的 `ts_mean(divide(...), 66)` 在稀疏内幕数据上的黑盒语义无法从外部复现**：
  五种合理实现全落在 0.35–0.61，离 0.90 有稳定缺口；且平台不提供中间量观测（Python alpha 无输出通道）。
- **复刻的性价比已经很低**：即便对齐成功，收益只是「六维里 Operators per Alpha 少 9 个」；
  而当前每次实验 4 分钟、已跑 13 条，仍差 0.43 S + 2Y 破闸。
- **决策建议**：`leadEXnl` 按 **9 ops FASTEXPR 版 `Jj8qWmlx`** 交付；**Python 通道留给从零新开的候选**
  （一上手就写 Python 形态，不追求与 FASTEXPR 逐位一致，只追求自己过闸）。

### 6.4 可复用的两条经验

1. **Python alpha 里 `nan→0` 是系统性错误**：任何 [0,1] 打分体系下，把缺失填 0 等于「最低分=强空」。
   本颗上这一个 bug 值 0.82 S（0.92→1.74）。正解是填该腿的中性值（rank 用 0.5）。
2. **逐层对齐的顺序**：先 `rank(close)`、再 `ts_mean(close,22)`、再 `group_rank(close,sector)`——
   这三条全对上才能排除「框架/数据/分组」问题；本颗正是靠这个顺序把问题锁进 q 腿的。
