# DEU 全域数据集潜力扫描（按探针 SOP 第 0 步 + 历史闸）— 2026-10-14

**方法**：不跑新回测，用台账 + 字段库做零成本筛选（工具：`wq-brain-ra-deu/scripts/potential_scan.py`）。
**数据**：DEU 台账 **1326 条真实表达式行**（另有 **258 条标签行被剔除**）+ 字段库 4012 个字段。
**结论摘要**：扫描有效识别出 8 个「多腿强信号」、5 个「单信号近失带」数据集；**但经合规性核验后，全部高 S 历史都归因于同一条腿（预期变化率）——DEU 不存在第二条独立腿。这是对「DEU 已触顶」结论的第三次、且最系统的确认。**

## 一、扫描维度（全部零成本）

| 维度 | 含义 | 用途 |
|---|---|---|
| `avail` | cov≥0.6 的业务字段数（剔除分组轴） | 可用面大小 |
| `fams` | 概念族数（字段名首词聚类） | 跨族探针空间（SOP 核心：族内 PnL 相关 0.99，跨族才有新信息） |
| `zero` | α=0 字段占比 | 真空白程度 |
| `tested` | 已实测字段占比（**精确匹配**：code 分词 ∩ 字段名） | 未挖比例 |
| `bestS` / `maxfields` | 历史最优 S / 该行用到的业务字段数 | 信号强度 + **合规性**（≥2 字段 = 多腿 add，被禁形态） |
| `best1field` | 单业务字段行的最优 S | 合规可复现强度 |

**★ 关键前提：必须剔除标签行。** 台账里 `code` 形如 `R83` / `R102` / `RV+Vk65式` 的行是**配方引用**，不是表达式——本区 258 条（16%）。若不剔除，它们的 S 会被误判为「合规过闸」（首轮扫描即出现此假阳性，已修正）。

## 三、★★★ 决定性核验：高 S 行全部归因于同一条腿

对 **511 条 S≥1.58 的真实表达式行**做字段归因：

**⇒ 结论：DEU 台账中所有可识别的 S≥1.58 表达式，都包含同一条腿（预期变化率）。**
