### 因子定义与计算逻辑

```
"vector_neut(vector_neut(reverse(rank(divide(total_financing_cash_flow,assets_total_2))),rank(divide(free_cash_flow,assets_total_2))),rank(divide(operating_cashflow,assets_total_2)))"
```

**9 个算子调用**：`vector_neut ×2`、`reverse ×1`、`rank ×3`、`divide ×3`。

原始 15 算子版（`XgJL2eYl`）在每个 `divide` 的分子分母各套了一个 `ts_backfill(..., 252)`，共 6 个；压缩后全部去掉，**指标逐位相同**（见 §四）。

逐层拆开：

1. `div(筹资现金流, 总资产)` —— **外部融资依赖度**：单位资产撬动的外部融资净额。
   经济含义对应 Bradshaw–Richardson–Sloan 一脉的**外部融资异象**：高度依赖外部融资的公司，后续收益 systematically 偏低（融资往往伴随过度投资与估值高位）。
2. `reverse(rank(...))` —— 截面秩取反，做多低融资依赖、做空高融资依赖。
3. 第一层 `vector_neut(..., rank(自由现金流/总资产))` —— 剔除**自由现金流生成能力**这一公共维度。
4. 第二层 `vector_neut(..., rank(经营现金流/总资产))` —— 再剔除**经营现金流**维度，只留下无法被这两者解释的残差。

⚠ 合规说明：**这是单信号 + 残差入场**，不是两腿加权相加。`vector_neut` 是正交化（从 A 中剥掉 B 的成分），符合组合形态铁律允许的「残差入场」形态。

### ★ 真正的收获：`ts_backfill` 在本配置下是彻底的 no-op

注意两对**只差 `ts_backfill`** 的表达式，指标却是**逐位相同**：

- H2（9 算子，有 backfill）≡ H4（10 算子，有 backfill，位置不同）→ 都是 S 1.50 / F 0.96
- H3（7 算子，有 backfill）≡ H5（6 算子，**无** backfill）→ 都是 S 1.44 / F 0.84

**结论：在 `EUR / TOPCS1600 / nanHandling=ON` 下，`ts_backfill` 完全不改变数值路径。** 原表达式里那 6 个 `ts_backfill` 是纯粹的白费 —— 它们在季报口径的 MATRIX 字段上本来就没东西可填（nanHandling=ON 已经接管了空值）。

这条可推广：**未来所有 EUR 表达式，写 `ts_backfill` 前先问一句「我到底指望它填什么」** —— 大概率可以直接删掉，省算子且零代价。

### 6.6 ★★★ `hump` 误诊纠正：不是幽灵算子，是我用法错了

上一轮报告曾把 `hump` 标为「EUR 幽灵算子（2 次无 alpha_id）」并准备写入幽灵清单。**这是误诊。**

**真相**：`hump` 是 Time Series 类**真实**算子，`get_operators` 实测在册：

```json
{"name": "hump", "category": "Time Series", "scope": ["COMBO","REGULAR"],
 "definition": "hump(x, hump = 0.01)",
 "description": "Limits amount and magnitude of changes in input (thus reducing turnover)",
 "level": "ALL"}
```

而且**同一平台的 KOR 战役早已成功跑过十余条** `hump(..., hump=0.003)`（`KPNo2lgl` prod 0.5504）—— 我方在 EUR 用不了，只能是写法问题。

**根因 = keyword-only 参数。** 签名 `hump(x, hump = 0.01)` 里的 `=` 标记 `hump` 为**命名参数**，必须写 `hump=0.0012`。上一轮我写的是位置参数 `hump(x, 0.0012)`，平台回：

```
Invalid number of inputs : 2, should be exactly 1 input(s).
```

整条因此拿不到 alpha_id。这正是本仓库 **2026-09-07 已归档的 hump 事故**（`tests/unit/09_core/test_op_arity.py` 顶部有完整还原：当时 `hump(x, 0.005)` 过了本地闸、平台 CANCEL 掉整个 8 条 multisim，2 条畸形表达式烧掉 8 个槽位）。

本地闸离线复现（发批前必过）：

```
FAIL | hump(vector_neut(...), 0.0012)
  -> [ARITY] hump 只接受 1 个位置参数，实际 2 个（平台报 "Invalid number of inputs : 2, should be exactly 1 input(s)."）；
     多出的参数是命名参数，应写作 hump=0.0012　签名: hump(x, hump = 0.01)
PASS | hump(vector_neut(...), hump=0.0012)
```

**⇒ 沉淀为通用纪律：某算子「连续 N 次无 alpha_id」时禁止直接判「平台不存在」，必查三序：**
1. **签名参数形式**（是否 keyword-only）—— 离线秒判，报错直接给可照抄的修法；发批前必须过 `ensure_safe_for_dispatch`。
2. **输入类型兼容性**（算子是否接受该表达式产出的类型）。
3. **区域/档位限制**（最后才查，且必须先排除 1、2）。

⚠ **论坛帖也会给错写法**：FD69320《Gold 普遍有权限的 Operator 1》（33 赞）示例写 `hump(alpha_signal, 0.01)` —— **位置参数，平台会拒**。而正确帖（YZ54944 MEA 区）用 `"hump_values": [0.01, 0.005]` 命名式。**赞数不等于正确性，论坛抄写法必须过本地签名闸。**

**`hump` 工作原理**（论坛 FD69320，与官方 description 一致）：设昨日输出 u、阈值 `hump` ——
今日 x 与 u 之差 ≤ `hump` ⇒ **输出保持 u**（死区冻结，残余日间变化被完全压掉）；
差 > `hump` ⇒ 输出 = u ± `hump`（按变化方向）。等效于「限速器 + 死区门控」。
