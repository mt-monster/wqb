## 二、核对通过的健康点

1. **tools/ 孤儿率 3%**：160 个顶层脚本仅 5 个零引用（`_inventory_submit_ready`、`_robustness_zq87zzqO`、`hkg_d1_model_probe`/`2`、`kor_spre_read`——均探针/一次性遗留）。"新工具必须挂必经步骤"纪律生效。
2. **MCP 配置双文件是受控设计**：`.mcp.json`（权威，`${VAR:-default}` 跨平台写法）+ `mcp_config.json`（Claude Desktop 镜像），一致性有两个测试守护，非重复劳动。
3. **skills 单源多目标同步**：仓库 `Claude/skills/` 为源、4 个安装位为派生，`sync_skills.py --check` 可审计（本次正是靠它逮到漂移）。
4. **`.gitignore` 完备**：`.env`、`__pycache__`/`*.pyc`、`.workbuddy/`、各 Agent 安装位均不入 git——磁盘上大量 pyc 只是本地产物，不污染仓库。
5. **`wqb_db_mcp.py`（110 KB）在根目录是正确位置**：`.mcp.json` 的 wqb-db 入口直接指向它，71 处引用。

## 三、发现的问题

- `wq-brain-campaign-toolkit/config/methodology_rules.json`（仓库 10-01 01:02 新 / 安装位 09-30 22:50 旧）
- `brain-make-some-gem/scripts/trailSomeAlphas/run_pipeline.py`（仓库 01:00 新 / 安装位 22:32 旧）

⚠ 仓库文件修改时间就是当前时刻附近——可能有并行会话正在编辑，sync 前建议确认无人正在写这两个文件。

### P1 报告三头分流
- `output_report/`（119 件）＝区域/战役 ideas 与评审报告流，纯 .md，语义干净；

## 四、建议（按收益/成本排序）

1. **跑 `python tools/sync_skills.py` 消漂移**（先确认无并行会话在写那 2 个文件）——一条命令，P0 归零。
2. **根目录收敛**：论坛工作台工具链 6 件套打包进 `tools/forum_workbench/`；删 `_junit_tmp.xml`；`alpha模板.docx` 入 `data_ref/`。引用点只有工具链内部 + 一篇历史报告，迁移成本极低。
3. **报告单源化**：定 `output_report/` 为唯一报告出口；`reports/` 里的 .py 脚本并入 `tools/`（顺手消掉 mining/tools 模糊的同类项），rollback JSON 入 `cache/`，两个数据子目录并入 `tracking/` 或 `docs/experience/`；`results/` 整体并入 `cache/`（checkpoint 语义）并把它从 AGENTS.md 补写或删除。
4. **给 logs/ 与 cache/ 加 7 天滚动清理**（`wq_daily_refresh.py` 里加一段即可，它已经是日跑入口）。
5. **AGENTS.md 同步**：attic 行改写为"日期化归档包"现状；补 `results/`（若保留）、`findings/progress/task_plan` 三件套的声明。
