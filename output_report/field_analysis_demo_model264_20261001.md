### ⭐ 命名结构解析（本层的核心产出）

字段名 = `mdl264_<指标族>_<类型后缀>`，**后缀是语义关键**：

| 后缀 | 数量 | 含义（据 description 实证） |
|---|---|---|
| `_l1` | 36 | P(**fall**) — 未来下跌概率 |
| `_l2` | 36 | P(**neutral**) — 未来中性概率 |
| `_l3` | 36 | P(**move-up**) — 未来上涨概率 |
| `_class` | 95 | 三分类**众数标签**（1=跌/2=中性/3=涨） |
| `_se` | 66 | 带预期口径（FY1 BPS/DPS diffusion）的同类概率 |
| `_rg`/`_am`/`_bb`/`_acf` | 24 | 各指标族特有变体 |
| 其余 | — | 期间/口径标记（`m1d`/`m1r`/`m3d`/`fy1`/`r1m`/`d1m`） |

**机制本质**：这是一个「**预测各底层指标未来趋势方向的三分类概率模型**」数据集 —— 底层指标涵盖技术指标（adl/atr/cci/clv/cmf/bb…）+ 基本面比率（bookp/divyld/dpmo…）+ 分析师预期（eps_sur_decay/es_bps_fy1…）。

## L3 · 语义归类 —— "落台账，划定字段池边界"

```
python tools/field_semantic_classify.py --region GBR --dataset model264 --write-ledger
```

| 项 | 结果 |
|---|---|
| 信号字段 | **380（100%）** |
| 非信号黑名单 | 0 |
| 经济大类 | growth 304 / profitability 64 / valuation 12 |
| 冷门率 | 100%（users ≤ 9） |
| 台账键 | `GBR/s1_semantic_model264` |

### ⚠️ 归类法的已知局限（本演示的重要观察）

304 个**技术指标**（adl/atr/cci/bb…）被归类器打入 **`growth`** —— 明显失真。原因是 `field_semantic_classify.py` 的经济大类口径偏**财报**（估值/盈利/成长/现金流…），遇到 model 类数据集时退化。

**这不是 bug，是归类法的边界**：
- 归类**能做**：signal/blocked 分界（决定字段能否入表达式）、给 GEM 划池
- 归类**做不到**：识别信号形态、判断哪个字段有超额
- → **必须靠 L4 的机制推理补上**

## L4 · 代表字段 → 机制概念（唯一产出"信号"的层）

### 4.1 底层指标族盘点

去掉期间/后缀后：**380 字段 = 155 个底层指标族**，其中 **36 个族的 `l1+l2+l3` 三分类齐全**。

按 alphaCount（= 已被使用/验证的程度）排序 Top：

| 指标族 | 说明 | maxAC | maxUsers |
|---|---|---|---|
| `eps_sur_decay` | EPS Surprise with Decay | **6** | 1 |
| `bookp` | Book-to-Price | 4 | 3 |
| `bb` | Bollinger Bands | 3 | 1 |
| `ips` / `ocl` / `fincf` | — | 3 | 1–3 |
| `lda` / `m1d_1yf_spe` / `od` / `lco` | — | 2 | 1–2 |

### 4.2 ⭐ 核心机制假设：三分类结构的"净方向"信号

**最优雅的用法**：三个概率天然构成**单一价差信号**（项目铁律允许的形态，非拼腿）：

```
净方向 = P(up) − P(fall) = l3 − l1
```

- **经济含义明确**：净上涨概率（不是"两条独立信号相加"）
- **合规形态**：`subtract(rank(A), rank(B))` 单一价差，**有经济含义** —— 项目白名单明确放行
- **信息更完整**：`l2`（中性概率）可作**不确定性门控**（`l2` 高 → 趋势不明 → 降低暴露）
- **零竞争**：这些 `l1/l2/l3` 字段全部 users=0

**候选信号形态**（待实证，均需避开 L1 判死的"简单结构"）：

| # | 假设 | 表达式骨架 | 匹配塔 |
|---|---|---|---|
| H1 | 净上涨概率 | `subtract(rank(mdl264_X_l3), rank(mdl264_X_l1))` | MODEL / 其他 |
| H2 | 不确定性门控 | `trade_when(mdl264_X_l2 < 0.5, 净方向, -1)` | 门控复用 |
| H3 | 概率分布分歧 | `ts_stddev` / `P(up)·P(fall)` 交叉项 | 复合结构 |
| H4 | 跨指标族一致性 | 多族净方向求 `group_zscore` 后取符号一致性 | 跨族 |

> ⚠️ 全部必须**避开** `rank(f)`/`ts_delta(f,5)` 这类简单结构（L1 判死）。

### 4.3 代表字段选取（每族 ≤2 代表 + 3 冷门候选）

| 类别 | 选取 | 理由 |
|---|---|---|
| 代表（高 alphaCount） | `mdl264_eps_sur_decay_{l1,l2,l3}` | ac=6 最高，已被验证有信号 |
| 代表（高 users） | `mdl264_bookp_{l1,l2,l3}` | users=3 最高 |
| 冷门候选 | `mdl264_adl_{l1,l2,l3}` / `mdl264_amihud_{l1,l2,l3}` / `mdl264_bb_{l1,l2,l3}` | users=0 + 覆盖佳 |

## 结论

1. **model264 是高价值的未挖数据集**：380 字段全 MATRIX、全 coverage=1.0、83% 零竞争、valueScore 5、pyramid×1.7。
2. **唯一约束是结构级的**：禁简单排名/时序，禁 `other455×model264` 族，其余方向开放。
3. **最佳信号形态是三分类净方向** `l3 − l1`（合规单一价差），比任何"拼腿"都优雅。
4. **归类（L3）必要但不充分**：它划边界，不产信号；真正的信号来自 L4 的机制推理。
5. **下一步（需决策）**：对 H1 假设的 36 个族各跑 8 探针（`|S|≥0.5` 才扩批），配额成本可控。
