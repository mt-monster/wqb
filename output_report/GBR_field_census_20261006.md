## 四、两个必须知道的口径陷阱

1. **本地 catalog 双向不一致**：`star_val_*` 字段行在两次查询之间**从本地消失**（并发会话重写）；
   平台**不存在** `star_val_earnings_measure_type`（本地有）；`quant_factor_lib`（290 字段）在 GBR 全是 VECTOR + cov 0。
   ⇒ **字段存在性只信平台 `validate_expressions`**。
2. **平台侧枚举不完整**：`GET /data-sets?region=GBR&universe=TOP700&delay=1` **只返回 50 个数据集**，
   本地 catalog 有 205 个 ⇒ **"扫遍所有数据集"在平台 API 层面做不到**，只能用本地 catalog 近似。

## 五、为什么"未测 88%"不等于"还有 88% 机会"

GBR 的产出**高度集中在两类机制**（跨 180+ 条实测）：
1. **原始量在时间上的变化**（`ts_delta` + 短窗 8–13）：信用 PD / 杠杆 / 违约概率 / 资产漂移 / 估值 / 股息率；
2. **收益率口径的前瞻量**（E/P、股息率）。

而**派生分（概率 / 百分位 / 相似度 / PCA / 评分 / 计数 / 增速）在 GBR 上 6 次独立验证全部无效**。
未测的 2030 字段里，**约 8 成属派生分** ⇒ 这才是"未测很多但机会很少"的真实原因。
